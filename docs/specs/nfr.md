# 非功能需求

## NFR-001：安全性（Security）

優先級：P0（Critical）

### NFR-001.1：驗證安全性（Token 管理）

**需求陳述**：所有使用者 Session 必須透過安全的 Token 機制（JWT）進行驗證。Token 在閒置超過 8 小時後必須自動失效。勾選「記住我」時，Token 有效期延長至 30 天。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 預設 Token 閒置逾時 | 8 小時 |
| 「記住我」Token 有效期 | 30 天 |
| Token Payload 必含欄位 | user_id, role, issued_at, expiration |
| Token 失效方式 | 伺服器端 blocklist 或 Refresh Token 撤銷 |

**驗收標準**：

- Given 使用者目前有一個有效的 Session，When Session 閒置時間超過 8 小時，Then Token 失效，使用者必須重新進行驗證
- Given 使用者登出，When 使用舊 Token 發送 API 請求，Then 系統回傳 HTTP 401 Unauthorized

**受影響功能**：F001, F002, F003

---

### NFR-001.2：授權強制執行（RBAC）

**需求陳述**：每個 API 端點必須強制執行基於角色的存取控制（RBAC）。未授權的存取嘗試必須回傳 HTTP 403 並留下日誌記錄。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 角色類型 | admin, user |
| 未授權回應碼 | HTTP 403 Forbidden |
| 日誌記錄 | 每次未授權存取嘗試必須記錄 |

**驗收標準**：

- Given User 角色帳號嘗試存取 Admin 專屬端點，When 請求被系統處理，Then 系統回傳 HTTP 403 Forbidden，並記錄該次嘗試至日誌

**受影響功能**：所有需要權限控制的功能（F004-F008, F010-F016）

---

### NFR-001.3：密碼安全性

**需求陳述**：密碼必須使用 bcrypt 進行雜湊處理。明文密碼絕不能被儲存或出現在任何日誌中。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 雜湊演算法 | bcrypt（或同等強度） |
| 最低成本因子（cost factor） | 10 |
| 最短密碼長度 | 8 個字元 |
| 明文密碼出現於日誌 | 絕不允許 |

**驗收標準**：

- Given 一個新帳號以密碼建立，When 密碼被儲存至資料庫，Then 密碼以 bcrypt 雜湊形式儲存（非明文），成本因子 >= 10

**受影響功能**：F001, F002, F004, F009, F010

---

### NFR-001.4：資料來源憑證保護

**需求陳述**：資料庫連線憑證（密碼）必須使用 AES-256 或同等強度演算法在靜態時加密。憑證絕不能出現在 API 回應或應用程式日誌中。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 加密演算法 | AES-256（或同等強度） |
| API 回應中密碼呈現 | 遮罩方式（例如 `****`） |
| 日誌中出現憑證 | 絕不允許 |

**驗收標準**：

- Given 一筆資料來源記錄包含資料庫連線憑證，When 透過 API 取得該記錄，Then 密碼欄位以遮罩方式呈現，且絕不以明文回傳

**受影響功能**：F011, F012, F013, F015

---

### NFR-001.5：傳輸安全性

**需求陳述**：用戶端與伺服器之間的所有通訊必須使用 HTTPS。內部服務間通訊也必須加密。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 最低 TLS 版本 | TLS 1.2 |
| HTTP 明文通訊 | 絕不允許 |

**驗收標準**：

- Given 用戶端發送 HTTP（非 HTTPS）請求，When 伺服器收到請求，Then 請求被拒絕或自動重導至 HTTPS

**受影響功能**：所有功能

## NFR-002：效能（Performance）

優先級：P0（Critical）

### NFR-002.1：API 回應時間

**需求陳述**：在正常負載下，標準 CRUD 操作的 API 回應時間第 95 百分位數必須低於 500ms。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| p95 回應時間 | < 500ms |
| 正常負載定義 | 最多 50 位並發使用者 |
| 適用操作 | 標準 CRUD（建立、讀取、更新、刪除） |

**驗收標準**：

- Given 系統處於正常負載（最多 50 位並發使用者），When 發出一筆 CRUD API 請求，Then 第 95 百分位數回應時間低於 500ms

**受影響功能**：所有 API 端點

---

### NFR-002.2：並發使用者數

**需求陳述**：系統必須支援至少 100 位並發已驗證使用者，且回應時間維持在可接受範圍內。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 最低並發使用者數 | 100 人 |
| 回應時間降級上限 | 單一使用者基準值的 2 倍以內 |

**驗收標準**：

- Given 100 位使用者同時完成驗證並進行操作，When 他們執行標準操作（清單瀏覽、查看、編輯），Then 系統回應時間維持在單一使用者基準值的 2 倍以內

**受影響功能**：所有功能

---

### NFR-002.3：資料來源連線測試時間

**需求陳述**：資料來源連線測試操作必須在 10 秒內回傳結果（成功或失敗）。系統必須具備逾時機制以終止長時間未回應的連線嘗試。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 連線測試逾時 | 10 秒 |
| 逾時後行為 | 回傳失敗結果，狀態設為「已中斷」 |

**驗收標準**：

- Given Admin 對某資料來源發起連線測試，When 目標資料庫無回應，Then 測試在 10 秒內逾時，並回傳失敗結果

**受影響功能**：F015, F016

---

### NFR-002.4：儀表板載入時間

**需求陳述**：資料來源狀態監控儀表板必須在 2 秒內完成初始內容渲染，包含最多 50 個資料來源的彙整狀態資料。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 初始渲染時間 | < 2 秒 |
| 最大資料來源數量（測試基準） | 50 個 |

**驗收標準**：

- Given 系統中設定了 50 個資料來源，When Admin 開啟狀態監控儀表板，Then 儀表板含狀態資料在 2 秒內完成渲染

**受影響功能**：F016

---

### NFR-002.5：清單／搜尋效能

**需求陳述**：帳號清單與資料來源清單端點在資料量不超過 1,000 筆時，必須在 500ms 內回傳分頁結果。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 分頁回應時間 | < 500ms |
| 最大資料量（測試基準） | 1,000 筆 |
| 預設每頁筆數 | 20 筆 |

**驗收標準**：

- Given 系統中有 1,000 筆帳號或資料來源記錄，When Admin 請求分頁清單，Then API 在 500ms 內回傳結果

**受影響功能**：F005, F012, F046, F047

---

### NFR-002.6：擷取任務清單效能

**需求陳述**：擷取任務清單端點在資料量不超過 1,000 筆時，必須在 500ms 內回傳分頁結果。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 分頁回應時間 | < 500ms |
| 最大資料量（測試基準） | 1,000 筆 |
| 預設每頁筆數 | 10 筆 |

**驗收標準**：

- Given 系統中有 1,000 筆擷取任務記錄，When Admin 請求分頁清單，Then API 在 500ms 內回傳結果

**受影響功能**：F018

---

### NFR-002.7：擷取監控儀表板效能

**需求陳述**：擷取監控儀表板必須在 2 秒內完成初始內容渲染，包含最多 50 個擷取任務的彙整狀態資料。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 初始渲染時間 | < 2 秒 |
| 最大擷取任務數量（測試基準） | 50 個 |

**驗收標準**：

- Given 系統中設定了 50 個擷取任務，When Admin 開啟擷取監控儀表板，Then 儀表板含狀態資料在 2 秒內完成渲染

**受影響功能**：F024

---

### NFR-002.8：排程引擎效能

**需求陳述**：排程引擎每分鐘一次的掃描操作必須在 5 秒內完成，包含最多 200 個擷取任務的 cron 比對。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 排程掃描時間 | < 5 秒 |
| 最大任務數量（測試基準） | 200 個 |

**驗收標準**：

- Given 系統中設定了 200 個已啟用的擷取任務，When 排程引擎執行定期掃描，Then 掃描與 cron 比對在 5 秒內完成

**受影響功能**：F023

---

### NFR-002.9：Raw Data 寫入效能

**需求陳述**：擷取任務執行時，從外部資料來源讀取並寫入 AppDB raw data 表的批次 INSERT 作業，在百萬筆資料的場景下必須能穩定完成，且每批次（1,000 筆）的寫入時間不超過 5 秒。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 每批次寫入時間 | < 5 秒（1,000 筆/批次） |
| 百萬筆全量寫入（測試基準） | < 2 小時 |
| 批次大小 | 預設 1,000 筆（可透過 `EXTRACTION_BATCH_SIZE` 配置，範圍 100-10,000） |
| 記憶體使用 | 單一擷取任務不超過 512MB |

**驗收標準**：

- Given 外部資料來源包含 1,000,000 筆資料，When 系統以全量模式執行擷取任務，Then 所有資料成功寫入 AppDB raw data 表，總執行時間不超過 2 小時，每批次寫入時間不超過 5 秒

**受影響功能**：F021, F023

---

### NFR-002.10：Raw Data 預覽查詢效能

**需求陳述**：Raw data 預覽 API 在百萬筆資料的場景下，前段分頁查詢（page <= 100）必須在 2 秒內回傳結果。已索引欄位排序的查詢同樣必須在 2 秒內回傳。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 前段分頁查詢回應時間（page <= 100） | < 2 秒 |
| 後段分頁查詢回應時間（page > 1000） | < 5 秒 |
| 已索引欄位排序回應時間 | < 2 秒 |
| 最大資料量（測試基準） | 1,000,000 筆 |
| 預設每頁筆數 | 50 筆 |

**驗收標準**：

- Given raw data 表包含 1,000,000 筆資料，When Admin 請求 page=1&limit=50 的分頁查詢，Then API 在 2 秒內回傳結果
- Given raw data 表包含 1,000,000 筆資料且 `_cdmp_id` 已建立索引，When Admin 請求以 `_cdmp_id` 排序的查詢，Then API 在 2 秒內回傳結果
- Given raw data 表包含 1,000,000 筆資料，When Admin 對非索引欄位排序，Then API 回傳資料並附帶效能警告

**受影響功能**：F026

---

### NFR-002.11：動態建表效能

**需求陳述**：首次執行擷取任務時的動態建表作業（讀取來源表 metadata + 建立 AppDB raw data 表）必須在 10 秒內完成。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 動態建表時間 | < 10 秒 |
| 最大欄位數量（測試基準） | 100 個欄位 |

**驗收標準**：

- Given 外部來源表包含 100 個欄位，When 系統首次執行該擷取任務並進行動態建表，Then metadata 讀取與 raw data 表建立在 10 秒內完成

**受影響功能**：F021, F023

---

### NFR-002.12：孤兒回收效能

**需求陳述**：系統啟動時的孤兒任務回收機制（F038）必須在 5 秒內完成全部回收作業，不應顯著延遲應用程式啟動時間。

**具體閾值**：

| 項目 | 閾值 |
|------|------|
| 回收總執行時間 | < 5 秒 |
| 啟動延遲增量 | < 5 秒 |
| 預期孤兒數量（測試基準） | 個位數（< 10 筆） |

**驗收標準**：

- Given 資料庫中有 10 筆孤兒擷取任務和 10 筆孤兒 ETL Pipeline，When 系統啟動執行孤兒回收，Then 回收作業在 5 秒內完成，應用程式啟動時間增量不超過 5 秒

**受影響功能**：F038
