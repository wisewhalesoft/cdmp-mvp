## Architectural Decisions

1. **DataSource Optional**：F054 AC-2b atomic transaction 需 DataSource，但 unit test mock 無法注入，故以 `@Optional()` 修飾；E2E 真實 DI 永遠注入。Unit test 走非 atomic 但行為正確的 fallback path（mock 觀察即足）。
2. **Audit log SCORING_INTEGRITY_WARN 寫入路徑**：透過 entity union 已支援的字串型 action 直接寫入（writeAudit 用 cast）；ScoringIntegrityCheckService 自行管理 audit 批次寫入。
3. **fn_calc_tier_level 部署**：採 `fs.readFileSync` 讀 `src/database/functions/*.sql` 後 raw query 執行；dist build 時須以 nest-cli copy assets 同步 sql 檔（migration 已加雙路徑 fallback）。
4. **fn_resolve_column_value helper**：plpgsql 等價於 JS layer 的 `resolveColumnValue`；目前只實作可從 ob_pool_data 直接取的欄位（LIST_MONTH / PROJECT_TP / CAR_YEAR / COMMISSION），其他客戶屬性留待 v2.1 join customer_core。
5. **warning_summary 合併策略**：採逗號分隔字串（VARCHAR(100)），相容既有 entity；多警告碼共存時前端 split 即可。
