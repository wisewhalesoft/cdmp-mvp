## 3. Tier 分佈比對（⚠️ 不吻合 — 評分卡/card 模型未對齊）

| 名單 | Legacy（映射後） | CDMP |
|---|---|---|
| 001 | T1=69.3% T2=22.8% T3=7.8% | **T3=100%** |
| 002 | T1=8.2% T2=62.2% T3=29.6% | **T3=100%** |
| 003 | T3=83.8% T4=16.2% | **T4=100%** |

**根因（已查證，非比例問題）**：
- CDMP score **有真實變化**（001: 81~152、003: 83~155）→ 計分引擎（F098/F099/F100）正常運作。
- 但 score 全落入**單一 card_level**（001/002 全 D、003 為 C/D）→ 單一 tier。
- 對照 legacy `OBLEVELCARD_LEVEL` 區間（type-S：D=0~152、C=153~168、B=169~190、A=191+）：score 81~152 落 D 是「依該卡設定正確」。
- legacy 之所以有 T1/T2/T3 spread，是因為**案件分屬不同 card_type（S/H/E…）→ 不同分數區間 → 不同 card_level → 不同 tier**；CDMP 對這批名單的 **card_type 指派 + 評分卡設定（OBLEVELCARD_*/OBTIER）未對齊 legacy**，導致 card_level/tier 退化為單一值。

→ **要讓 tier 維度可比，需比照比例匯入：載入 legacy `OBLEVELCARD_COLUNM/LEVEL/SCORE/VERSION` + `OBTIER`，並對齊 card_type 指派邏輯**（CSV 已 dump 在 `reference/DumpData/`，本次未匯入）。
