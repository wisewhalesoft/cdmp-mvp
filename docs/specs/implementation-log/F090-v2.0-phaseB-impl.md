# F090 v2.0：ob_pool_data_list 單源化收尾 — 實作日誌（Phase B）

## 摘要

依 F090 spec v2.0（AD-E07-25 DP-AD25-1 單源化）落地：`data_source` 值域由
`'etl_legacy'` / `'monthly_run'` 雙值單源化為**單一值 `'etl_load'`**。Phase A 已完成
（月名單分派改寫 `ob_monthly_run_result`，不再寫 `ob_pool_data_list`），本階段為應用層值域
收尾，**不改 production 月名單分派案件數**（僅資料來源語意 + 批次標記）。

依 AD-E07-25 §25.3，`partition_replace`（partitionColumn=`data_source`，
partitionValue=`'etl_load'`）即達成 `DELETE WHERE data_source='etl_load'` 後 INSERT、
每列填 `'etl_load'`；`fullMode` 維持 `false`（BR-3：引擎層不 TRUNCATE）。單源化後本表
僅 `'etl_load'` 一值，partition DELETE 與全量 DELETE 等效（殘留 `monthly_run` / NULL
舊列由全量覆寫自然淘汰，DP-AD25-5）。**v2.0 不新建 migration**（m291 已於 v1.0 建立）。

## 架構決策 / 落地選擇

- **採 partition_replace 而非新增「全量 DELETE」load mode**：AD-E07-25 §25.3 明示
  「可改全量 DELETE 或 `DELETE WHERE data_source='etl_load'`，二者等效」。單源化後
  partition DELETE 即等效全量，最小變更、不破既有 27 個 partition_replace handler 測試。
- **TS-F090-ETL-002v2「清除 monthly_run/NULL 殘留」之全量 DELETE 語意**：需真 PG
  TestContainer 驗證（本專案未裝）；殘留列由全量覆寫自然淘汰（DP-AD25-5），去重不依賴
  `data_source` 過濾（[F091 BR-5] / RGv2-002），故正確性不受影響。handler 層以
  mock queryRunner 斷言 partition DELETE/INSERT 行為（與 v1.0 既有測試慣例一致）。
- **m291 不新建**：v2.0 為應用層值域說明變更（DP-AD25-1），schema 不變。

## 須確認之處

無阻擋。`data_source='etl_load'` 之 partition DELETE 在單源化後與全量 DELETE 等效，
符合 spec；若日後業務要求「實體清除既有 monthly_run/NULL 殘留」需另開 data migration
（spec 明示由全量覆寫自然淘汰，本階段不處理）。
