## Architectural Decisions

1. **matchType 無預設值（BR-8）**：DimensionModal 初始 matchType=''；submit 前若未選顯示 inline error「請先選擇比對模式 (matchType)」。對齊 spec「無預設值」要求。
2. **MatchTypeSwitchConfirmModal**：採新建獨立 component（內嵌於 DimensionEditModal）。aria-modal=true + ESC 關閉 + autoFocus 取消按鈕（基本 focus trap）。警告文字含「將清空 N 筆既有 score 列」對應 AC-2b。
3. **COMPOSITE 6 色循環著色**：採簡單 hash(level1) % 6 對應 `COMPOSITE_GROUP_COLORS` 陣列。同 level1 群同色，提升可讀性。
4. **ScoringWarningBanner map 結構**：採 `ISSUE_TYPE_DESCRIPTIONS: Record<string, string>` mapping。未來新增警告類型只需擴充 map，render 邏輯不需修改（對應 task §2「使用 map 結構支援未來插拔」）。
5. **後端 warning_summary 整合策略**：後端目前以逗號分隔字串保存（VARCHAR(100)），`extractWarningSummary()` 在 run-summary-page split → 每碼變成一筆 issue。當後端日後改回結構化 JSON 時可直接替換此 helper。
6. **既有 fallback matchType 推導**：當後端 GetScoringResponse 尚未補 matchType 欄位時，`deriveMatchType()` 由 scores 結構推導（level1+level2 → COMPOSITE / level1 → CATEGORY / level2 → RANGE），確保 UI 在 transition 期間仍可正常顯示 chip。
