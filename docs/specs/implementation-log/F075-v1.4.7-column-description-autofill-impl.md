## Architectural Decisions

### 命名規範（嚴格遵守上游 spec / system-architect 決議）
- API response field：`columnDescription`（camelCase, optional, omit 而非 null）
- SQL Server 屬性：`MS_Description`（原始大小寫）
- Executor method：`getColumnDescriptions`（複數）
- 前端 testid：`displayname-autofilled-hint`
- 前端 JS helper：`autoFillDisplayNameFromColumn`
- 禁用詞 `description` / `chineseName` / `label` / `comment` / `remarks` 全部不出現在本 PR DTO / 變數 / testid

### Module wiring（方案 A）
- 直接在 `ExtractionTaskModule` providers 補 `MSSQLExecutor` 並 exports，避免將 SQL Server 細節滲透到 PooldataFieldModule
- `PooldataFieldModule` 透過 `imports: [ExtractionTaskModule]` 取得 MSSQLExecutor，符合 NestJS DI 慣例

### Service 設計細節
- `Promise.all` 並行 information_schema 查詢與 ExtractionTask 查詢（無相依），降低總延遲
- MSSQLExecutor 呼叫包 try/catch 降級為 `logger.warn`（不重拋），確保使用者體驗：SQL Server 暫時不通也能正常列出欄位清單
- ExtractionTask 查詢 `{ source_table: 'OBPOOLDATA' }` order by `created_at DESC`，**不限 status**（spec 定案）
- merge 用 spread 條件式 `...(desc ? { columnDescription: desc } : {})` 而非賦 null/undefined，保證 `JSON.stringify` 天然 omit 該 key

### Frontend 設計細節
- Mode 隔離：自動填入入口僅在 create modal 的 dropdown `onColumnSelected` 內呼叫；Edit Modal 為獨立 `<EditFieldModal>` component 不會觸發（component 結構天然隔離，無需額外 guard 邏輯）
- hint 重置 trigger：使用者鍵入 input、resetCreateForm（關閉/重開 modal）
- hint UI 採 `text-[11px] text-primary` + Sparkles icon，緊接 input 下方，與既有「業務可讀中文標籤…」說明文字同 div
