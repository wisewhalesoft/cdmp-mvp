## 架構決策

- **In-Memory 策略**：所有 Merge/Dedup/Transform 在 Node.js 記憶體完成，符合架構規格
- **引用計數釋放**：PipelineRunner 在拓撲排序後預計算 refCount，下游完成後遞減釋放上游輸出
- **NodeDispatcher 註冊制**：8 種 Handler 透過 `register()` 註冊，未知 nodeType 拋出明確錯誤訊息
- **LogUpdateCallback**：PipelineRunner 透過 callback 模式回寫 node_logs，解耦 DB 依賴
- **QueryRunner 生命週期**：由 ExecutionService 建立並在 finally 中釋放，確保連線不洩漏
- **既有 etl-transforms.ts 複用**：DerivedFieldHandler 的 mergePhone 直接呼叫既有函式
