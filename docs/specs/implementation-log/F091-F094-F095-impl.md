## 關鍵實作決策

### F091 v2.0 — 特例 DELETE SP 修正 + 共用 trigger
- **觸發修正（SP UTF-16LE 解碼 ground truth）**：R-PERIOD-MOTORCYCLE = `期中`+`機車`；R-PERIOD-XIAOZI = `期中`（排除條件 `spec_name 含小資`，非 v1.0 誤判之「滿」）；R-YEAR-ABOVE = `年以上`（`parseInt(year_produ ?? '1900') < workdt.getFullYear()-15`，NaN<cutoff=false → 非數值保留）。詐騙白牌不變。
- **抽共用純函式**：trigger 判斷統一移至 `special-rules.ts` `matchesSpecialRule`，chain 的 `applyListNmSpecialDeletes` 與 F095 service 共用同一份（F091-test RGv2-001/005 grep guard + special-rules CON-001 import 路徑驗證 + 一致性測試 6 個 list_nm 驗 `chain.appliedRuleIds === deriveAppliedSpecialRules`）。
- **去重上界升級**：`computeDedupWindow` 改 async，`SELECT MAX(assignday) WHERE assignday IS NOT NULL`，NULL→workdt-1，否則 MIN(maxAssignday, workdt-1)（yyyyMMdd 字串字典序比較）。簽名變更只影響 chain 內部呼叫（pipeline / stage0 / backfill 只呼叫 `executeStage1Chain`，簽名不變）。

### F094 — 月跑結果表落點切換（pipeline 關鍵 diff）
- pipeline 同時注入兩 repo：`poolDataListRepo`（ObPoolDataList，**去重唯讀來源**，AC-7）+ `resultRepo`（ObMonthlyRunResult，**寫入目標**）。
- `executeV1/V2(stage1Cases, ym, runId)` 每列帶 `run_id` + `result_status='PENDING'` + `emplid_deptid`（Stage 4）；交易內 `getRepository(ObMonthlyRunResult).save(...)`，**移除** `data_source='monthly_run'` 寫入 ob_pool_data_list。
- Stage 3/4 結果欄位（is_cr/cr_id/cr_nm、dept_id/emplid/emplid_deptid）皆寫本表（pipeline 全程 in-memory 組裝後單次寫入，落點即本表）。
- `assignment_run_snapshot` type=result 雙軌保留（DP-AD25-3）；`collectCrCandidates()` 不動（仍讀 snapshot）。
- migration / FK CASCADE 真實 PG 驗證：本專案無 PG TestContainer → migration spec 採 mock queryRunner + 靜態分析；FK CASCADE 行為以 better-sqlite3 in-memory pipeline spec（TS-F094-FK-001）涵蓋；真實 PG up/down 標 **DEFERRED**（staging 手動驗證）。

### F095 — appliedSpecialRules 唯讀呈現
- 後端 read-time derivation：`getFullSnapshot` 回 `deriveAppliedSpecialRules(entity.list_nm)`，**無新 DB 欄位 / migration**（DP-AD26-3）；與 F091 chain 共用同一 trigger utility（CON 一致性保證 UI = 月跑實際套用）。
- 端點對齊：實際 prefix `assignment/lists`，方法 `GET /:listNo/full-snapshot`（F095 §5.0 已對齊，非 AD §26.5 概念路徑 `assignment-lists/:listNo`）。
- 前端：prototype `27-list-definition.html` **已含** F095 唯讀區塊（conditions tab 內），React `ListDetailDrawer.ConditionsPanel` 拆出 `UserConditions` + `AppliedSpecialRulesPanel`，灰底卡 / 鎖頭 / 「系統規則·唯讀」pill / amber「依名單名稱觸發」vs 灰「系統強制·全名單套用」/ 空態提示，與 prototype 1:1 對齊。純唯讀（無 input/button/select/a）。容錯：appliedSpecialRules 未回傳隱藏整區塊。
