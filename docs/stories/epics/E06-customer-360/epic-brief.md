## Epic 目標

Customer 360 是 CDMP 平台面向業務使用者的客戶資料洞察模組，讓不同角色的使用者能從 ETL Pipeline 治理後的 `customer_core` 目標表中，獲取有價值的客戶洞察，達成「**可採取行動的客戶資料洞察**」之核心價值主張。

Phase 2 聚焦八項核心能力：
1. **客戶搜尋與清單** — 讓使用者快速找到目標客戶，支援多條件篩選
2. **單一客戶 360 檢視** — 整合 customer_core 所有維度的客戶完整側寫
3. **標籤管理** — 業務人員對客戶進行自訂分類、批次標記與篩選
4. **變更歷史與角色存取控制** — 追蹤客戶資料演進歷程、依業務角色設定欄位可見性與遮罩規則
5. **客戶名單匯出** — 依篩選條件匯出客戶清單為 CSV，支援行銷、分析師、主管進行下游分析
6. **客戶互動紀錄** — 業務、客服人員記錄與客戶的往來互動事件（僅可見自己的紀錄），主管可查看所有紀錄
7. **客戶群組統計報表** — 以標籤或篩選條件為維度，產出客戶群組的財務指標分佈與地區分佈統計，供主管與分析師使用
8. **資料品質回報機制** — 後端作業與分析師在覆核過程中發現資料異常時，可標記並回報，建立資料品質閉環

原 Phase 3 規劃的 US-067（變更歷史查詢）與 US-068（角色存取設定）已合併至 Phase 2（2026-04-02 業務決策）。

## 標籤體系定義（2026-04-07 業務確認）

E06 的標籤系統區分兩種類型，以滿足「公司統一分類」與「個人工作標記」的不同業務需求：

### 全域標籤（Global Tag）

| 屬性 | 說明 |
|------|------|
| 建立者 | 僅 Admin 可建立 |
| 可見範圍 | 全部使用者均可見 |
| 可用範圍 | 全部使用者均可將全域標籤貼到客戶上，或用於篩選 |
| 管理權限 | 僅 Admin 可編輯、刪除 |
| 典型場景 | 公司統一定義的分類，如「VIP」、「黑名單」、「高風險」 |
| 資料欄位 | `tag_type = 'global'`，`owner_id = NULL` |

### 自訂標籤（Custom Tag）

| 屬性 | 說明 |
|------|------|
| 建立者 | 一般使用者（業務、行銷、客服、分析師、主管）可自行建立；Admin 亦可建立 |
| 可見範圍 | **僅建立者本人**可見，不出現在其他使用者的標籤清單 |
| 可用範圍 | 僅建立者可使用（貼標、篩選）；無法被其他使用者使用 |
| 管理權限 | 建立者可編輯、刪除自己的自訂標籤；Admin 可管理所有人的自訂標籤 |
| 典型場景 | 個人工作標記，如業務個人的「跟進中」、行銷個人的「Q2 活動名單」 |
| 資料欄位 | `tag_type = 'custom'`，`owner_id = 建立者 UUID` |

### 名稱唯一性規則

- 全域標籤：名稱在全系統唯一（不可與其他全域標籤同名）
- 自訂標籤：名稱在同一 `owner_id` 下唯一（不同使用者可有同名自訂標籤）
- 全域標籤與自訂標籤之間**不受名稱衝突限制**（允許同名）

## 資料實體（新增）

### CustomerTag（標籤定義）

| 欄位 | 類型 | 說明 |
|------|------|------|
| id | UUID (PK) | 主鍵 |
| name | VARCHAR(50) | 標籤名稱 |
| color | VARCHAR(7) | 標籤色碼（HEX，如 `#3B82F6`） |
| description | VARCHAR(200) | 標籤說明（選填） |
| tag_type | ENUM('global', 'custom') | 標籤類型：全域或自訂，NOT NULL |
| owner_id | UUID nullable (FK) | 自訂標籤的建立者；全域標籤為 NULL（參照 accounts 表） |
| created_by | UUID (FK) | 建立者（參照 accounts 表） |
| created_at | TIMESTAMP | 建立時間 |
| updated_at | TIMESTAMP | 更新時間 |
| deleted_at | TIMESTAMP | 軟刪除時間 |

唯一約束：全域標籤 `name` 全系統唯一（UNIQUE on `name` WHERE `tag_type = 'global'`）；自訂標籤 `(name, owner_id)` 唯一（UNIQUE on `(name, owner_id)` WHERE `tag_type = 'custom'`）。

### CustomerTagAssignment（客戶標籤指派）

| 欄位 | 類型 | 說明 |
|------|------|------|
| id | UUID (PK) | 主鍵 |
| customer_id | UUID (FK) | 客戶 ID（參照 customer_core.customer_id） |
| tag_id | UUID (FK) | 標籤 ID（參照 customer_tags 表） |
| assigned_by | UUID (FK) | 指派者（參照 accounts 表） |
| assigned_at | TIMESTAMP | 指派時間 |

索引建議：`(customer_id, tag_id)` 唯一約束、`tag_id` 索引（用於依標籤查詢客戶清單）。

### customer_core_history（客戶資料變更歷史，Phase 2）

此表為 `customer_core` 的 SCD Type 2 歷史快照表，於 Phase 2 實作（US-067），紀錄每次 ETL 載入前後的欄位差異。詳細 Schema 定義見 US-067 Technical Notes。

## 雙維度分離 RBAC 設計（2026-04-07 業務確認）

E06 Customer 360 採用「雙維度分離 RBAC」策略，將存取控制拆分為兩個獨立維度：

### 維度一：欄位可見性（Field Visibility）— 動態設定

- **定義**：控制各業務角色能查看哪些 customer_core 欄位分類（A~H）的資料，以及敏感欄位是否遮罩
- **管理方式**：Admin 可在「角色權限管理」頁面動態調整，儲存於 `c360_field_visibility` 資料表
- **最小粒度**：以 customer_core 的 8 個欄位分類（A~H）為最小控制單位，不支援單一欄位細粒度控制
- **SSOT**：US-068 為欄位可見性管理的唯一權威來源，不另設獨立文件

### 維度二：功能操作權限（Feature Operation Permission）— 硬編碼

- **定義**：控制各業務角色能使用哪些 Customer 360 功能（如匯出名單、互動紀錄、統計報表等）
- **管理方式**：硬編碼於後端 RBAC Guard，不開放動態調整，確保系統行為邊界穩定
- **完整矩陣**：詳見 US-068 Technical Notes 中的功能操作權限矩陣

### Admin 定位（重要）

Admin 是**系統設定者**，非業務使用者：
- **欄位可見性維度**：Admin 始終具備所有欄位分類的完整存取權（full），不受 `c360_field_visibility` 設定影響
- **功能操作維度**：Admin 不預設具有業務功能（匯出名單、互動紀錄、統計報表等）；Admin 的可操作功能為角色權限管理、全域標籤管理、資料品質回報管理

**標籤體系補充說明**：一般使用者（業務、行銷、客服、分析師、主管）建立的標籤一律為自訂標籤，系統自動設定 `tag_type = 'custom'`，`owner_id` 為建立者。使用者僅能看到並操作全域標籤（唯讀，不可編輯刪除）及自己建立的自訂標籤。Admin 可透過標籤管理頁面查看系統中所有使用者的自訂標籤，並可在必要時進行管理。

**後端作業（作服）角色定位**（2026-04-03 業務確認）：後端作業角色主要場景為「貸款案件核准後的撥款前人工覆核」，需確認客戶基本資料正確性。此角色僅需查看客戶基本資料與財務欄位，不需記錄互動紀錄、操作標籤，或匯出名單。欄位可見範圍由 US-068 角色存取設定控制。

**Phase 2 角色存取**：E02 在 Phase 1 已建立六種業務角色的 Seed Data（US-017）。Phase 2 的 Customer 360 模組直接支援六種業務角色的存取控制，不再以 Admin / User 兩種角色作為暫行方案。角色細粒度的欄位可見性與遮罩規則由 US-068 定義與設定。

## 成功標準

- 使用者能在 2 秒內找到目標客戶（NFR-002）
- 單一客戶 360 頁面整合 customer_core 全部 8 個資料分類展示
- 標籤 CRUD 完整，支援批次標記至少 100 筆客戶
- 依標籤篩選客戶清單效能符合 NFR-002（500ms / 1000 筆以內）
- 變更歷史查詢（Phase 2，US-067）能追蹤至少最近 12 次 ETL 載入的差異，且僅限授權角色（客服/分析師/主管）存取
- 角色欄位可見性設定（US-068）Seed Data 部署後，各業務角色依業務方核准的初始矩陣正確顯示/遮罩/隱藏欄位分類
- 群組統計報表（US-072）：≤10 個全域標籤的群組查詢回應時間 < 3 秒；> 10 個時 < 10 秒
