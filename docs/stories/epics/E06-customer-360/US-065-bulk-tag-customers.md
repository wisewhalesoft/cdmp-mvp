# US-065：批次標記客戶

> **Story ID**：US-065
> **Epic**：[E06 — Customer 360](epic-brief.md)
> **優先級**：Should Have
> **階段**：Phase 2
> **預估點數**：8
> **變更說明（2026-04-07）**：新增 AC-10（後端作業角色呼叫批次標記 API 回傳 403）；Technical Notes 補充 Transaction 邊界說明

---

## User Story

**As a** 已登入的使用者（Admin 或一般使用者）
**I want** 在客戶清單中選取多位客戶，一次為他們批次新增或移除標籤
**So that** 我能高效率地對大量客戶進行分類標記，節省逐一操作的時間

---

## 驗收標準

### AC-1：進入多選模式
- **Given** 使用者在客戶清單頁面（US-060）
- **When** 使用者點擊清單左上角的「多選」按鈕，或勾選任一客戶列的 Checkbox
- **Then** 清單每列顯示 Checkbox，頂部操作工具列出現，顯示「已選取 N 位客戶」

### AC-2：全選當頁
- **Given** 多選模式已開啟
- **When** 使用者點擊清單標頭的「全選」Checkbox
- **Then** 當前頁面所有客戶列被選中，工具列更新「已選取 N 位客戶」

### AC-3：批次新增標籤（可用標籤範圍）
- **Given** 使用者已選取至少 1 位客戶
- **When** 使用者點擊工具列的「新增標籤」按鈕，開啟標籤選擇 Dialog
- **Then** 標籤選擇 Dialog 僅顯示：（1）所有 `tag_type = 'global'` 的全域標籤、（2）`tag_type = 'custom' AND owner_id = 當前使用者` 的自訂標籤；**不顯示其他使用者的自訂標籤**

### AC-4：批次新增標籤（執行操作）
- **Given** 使用者已選取至少 1 位客戶，並在標籤 Dialog 中選擇一個或多個標籤後點擊「確認」
- **When** 系統執行批次指派
- **Then** 系統為所有選取的客戶批次建立 customer_tag_assignment 記錄（跳過已有該標籤的客戶），顯示成功通知「已為 N 位客戶新增標籤（M 位客戶已有此標籤，略過）」

### AC-5：批次移除標籤（可用標籤範圍）
- **Given** 使用者已選取至少 1 位客戶
- **When** 使用者點擊工具列的「移除標籤」按鈕，開啟標籤選擇 Dialog
- **Then** 標籤選擇 Dialog 同樣僅顯示全域標籤 + 自己的自訂標籤（同 AC-3 的可見範圍規則）

### AC-6：批次移除標籤（執行操作）
- **Given** 使用者已選取至少 1 位客戶，並選擇目標標籤後點擊「確認」
- **When** 系統執行批次移除
- **Then** 系統為所有選取客戶中有該標籤指派的客戶批次刪除對應的 customer_tag_assignment 記錄，顯示成功通知「已從 N 位客戶移除標籤（M 位客戶無此標籤，略過）」

### AC-7：批次上限
- **Given** 使用者嘗試選取超過 200 位客戶進行批次標記
- **When** 使用者勾選超過 200 筆
- **Then** 系統顯示提示訊息「批次操作最多支援 200 位客戶，請縮小選取範圍」，超過 200 筆後無法繼續勾選

### AC-8：批次操作進度回饋
- **Given** 使用者確認批次標記操作（選取 100 位客戶）
- **When** 系統正在執行批次寫入
- **Then** 顯示進度指示（如載入 Spinner 或進度條），操作完成後顯示結果摘要通知

### AC-9：退出多選模式
- **Given** 多選模式已開啟
- **When** 使用者點擊「取消」按鈕或再次點擊「多選」按鈕
- **Then** 清單回到一般瀏覽模式，所有 Checkbox 取消勾選，工具列隱藏

### AC-10：後端作業角色不可執行批次標記操作
- **Given** 登入者角色為後端作業（作服）
- **When** 使用者嘗試呼叫批次標記 API（POST /api/v1/c360/customers/bulk-tag）
- **Then** 後端回傳 403 Forbidden；前端在客戶清單的多選模式工具列中不顯示「新增標籤」及「移除標籤」按鈕（功能操作權限硬編碼禁止後端作業角色執行批次貼標操作）

---

## Technical Notes

- 批次上限：Phase 2 設定為 200 筆，後端亦需驗證此限制
- 批次操作採用單一 API 呼叫（非逐筆呼叫），傳入 customerIds 陣列與 tagIds 陣列
- 重複指派跳過（冪等操作）：已有標籤的客戶不報錯，只記錄略過數量
- 批次操作在單一 DB Transaction 中執行，確保原子性
- **Transaction 邊界說明**：
  - **403 整批回滾**：若請求中含有無使用權限的 tagId（他人的自訂標籤），或呼叫者為後端作業角色，整批請求在進入 Transaction 前即回傳 403，不執行任何資料庫操作
  - **重複指派 skip 不回滾**：若部分客戶已有該標籤（重複指派），該客戶跳過（skip）不視為錯誤，不觸發整批回滾；其餘客戶正常完成指派
  - **超過上限回滾**：若 customerIds 陣列超過 200 筆，整批請求回傳 400，不進入 Transaction
- 後端驗證標籤使用權限：批次操作中的每個 tagId 必須屬於 `global` 或 `owner_id = 當前使用者` 的 `custom` 標籤；含有無權限 tagId 時，整批請求回傳 403 Forbidden
- 後端驗證角色操作權限：後端作業（`backend_ops`）角色呼叫此 API 時，後端 RBAC Guard 在進入業務邏輯前回傳 403
- 前端傳送的 tagIds 只能來自「可用標籤清單」（由 `GET /api/v1/c360/tags/available` 提供），不應允許手動輸入任意 tagId

### API 端點

**批次新增標籤**

- 端點：`POST /api/v1/c360/customers/bulk-tag`
- Request Body：
```json
{
  "customerIds": ["uuid1", "uuid2", "..."],
  "tagIds": ["uuid-tag1"],
  "action": "add"
}
```
- Response（200 OK）：
```json
{
  "action": "add",
  "processedCount": 100,
  "skippedCount": 5,
  "failedCount": 0
}
```
- 錯誤（400 Bad Request）：customerIds 超過 200 筆
- 錯誤（403 Forbidden）：tagIds 中包含無使用權限的標籤

**批次移除標籤**

- 與批次新增共用端點，`action` 改為 `"remove"`

## 測試案例

| # | 測試案例 | 預期結果 |
|---|---------|---------|
| 1 | 勾選 3 位客戶，點擊「新增標籤」，Dialog 只顯示全域標籤 + 自己的自訂標籤 | 他人的自訂標籤不出現 |
| 2 | 選擇全域標籤「VIP」批次新增給 3 位客戶 | 3 位客戶均成功指派「VIP」標籤 |
| 3 | 選擇自己的自訂標籤「跟進中」批次新增給 3 位客戶 | 3 位客戶均成功指派「跟進中」標籤 |
| 4 | 其中 1 位客戶已有「VIP」標籤，批次新增 | 成功通知顯示「1 位已有此標籤，略過」 |
| 5 | 批次移除 5 位客戶的「VIP」標籤，其中 2 位無此標籤 | 成功移除 3 位，通知「2 位無此標籤，略過」 |
| 6 | 嘗試選取 201 位客戶 | 系統提示批次上限 200，無法繼續勾選 |
| 7 | 點擊全選 Checkbox | 當頁 20 位客戶全部被選取 |
| 8 | 透過 API 傳入他人的自訂標籤 ID | 回傳 403 Forbidden |
| 9 | 批次操作中途點擊取消 | 操作已完成的部分保留（非 undo），退出多選模式 |
| 10 | 退出多選模式 | 清單回到一般瀏覽，Checkbox 消失 |

- [ ] 重複指派跳過邏輯實作完成（冪等操作）
