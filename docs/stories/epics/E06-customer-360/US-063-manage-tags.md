# US-063：管理標籤

> **Story ID**：US-063
> **Epic**：[E06 — Customer 360](epic-brief.md)
> **優先級**：Must Have
> **階段**：Phase 2
> **預估點數**：5
> **變更說明（2026-04-07）**：Admin 視角的 API Response 統一 `customTags` 鍵名；`ownerName` 僅在 Admin 視角回應中包含，一般使用者回應不包含

---

## User Story

**As a** 已登入的使用者（Admin 或一般使用者）
**I want** 查看、編輯與刪除標籤
**So that** 我能維護標籤系統的整潔度，修正標籤名稱或顏色，移除不再使用的標籤

> **設計決策**：標籤採用**單層扁平結構，不支援階層（父標籤／子標籤）**。管理介面不提供階層操作（無「設定父標籤」、「移動至子分類」等功能）。（2026-04-02 業務確認）
>
> **設計決策**：標籤管理清單依類型分為兩個區段顯示：「全域標籤」（所有使用者可見）與「我的標籤」（僅建立者可見）。Admin 可管理全部標籤（含所有人的自訂標籤）；一般使用者對全域標籤僅能唯讀，只能編輯／刪除自己建立的自訂標籤。（2026-04-07 業務確認）

## 驗收標準

### AC-1：一般使用者查看標籤清單（分區顯示）
- **Given** 一般使用者（業務、行銷、客服、分析師、主管）進入標籤管理頁面
- **When** 頁面載入完成
- **Then** 顯示兩個區段：
  1. **「全域標籤」區段**：顯示所有 `tag_type = 'global'` 的標籤，每列包含：標籤色彩圓點、標籤名稱、說明、已標記客戶數量、建立者；**不顯示編輯、刪除按鈕**（唯讀）
  2. **「我的標籤」區段**：顯示當前使用者建立的所有 `tag_type = 'custom'` 標籤，每列包含：標籤色彩圓點、標籤名稱、說明、已標記客戶數量、建立時間、操作按鈕（編輯、刪除）

### AC-2：Admin 查看標籤清單（全管理視角）
- **Given** Admin 進入標籤管理頁面
- **When** 頁面載入完成
- **Then** 顯示兩個區段：
  1. **「全域標籤」區段**：顯示所有 `tag_type = 'global'` 的標籤，每列顯示操作按鈕（編輯、刪除）
  2. **「自訂標籤」區段**：顯示系統中所有使用者的 `tag_type = 'custom'` 標籤，每列除標準欄位外，額外顯示「建立者姓名」，並提供操作按鈕（編輯、刪除）

### AC-3：編輯自己建立的標籤
- **Given** 使用者在標籤清單點擊自己建立之標籤的「編輯」按鈕（一般使用者只能編輯自訂標籤；Admin 可編輯任何標籤）
- **When** 編輯 Dialog 開啟
- **Then** 預填現有的標籤名稱、顏色與說明，使用者修改後點擊「儲存」，系統更新標籤資料，清單即時反映變更，並顯示成功 Toast 通知

### AC-4：一般使用者不可編輯全域標籤
- **Given** 一般使用者在全域標籤區段
- **When** 頁面載入完成
- **Then** 全域標籤列不顯示「編輯」與「刪除」按鈕，且一般使用者無法透過 API 編輯或刪除全域標籤

### AC-5：編輯標籤名稱重複驗證
- **Given** 使用者將標籤名稱修改為在有效 scope 內已存在的另一個標籤名稱
- **When** 使用者點擊「儲存」
- **Then** 顯示驗證錯誤「標籤名稱已存在，請使用不同名稱」

### AC-6：刪除無客戶指派的標籤
- **Given** 某標籤目前未指派給任何客戶，且當前使用者有權限刪除（Admin 或自訂標籤的 owner）
- **When** 使用者點擊「刪除」按鈕，並在確認 Dialog 中點擊「確認刪除」
- **Then** 系統軟刪除該標籤，從清單中移除，顯示成功 Toast 通知「標籤已刪除」

### AC-7：刪除已有客戶指派的標籤
- **Given** 某標籤已指派給至少 1 位客戶，且當前使用者有權限刪除
- **When** 使用者點擊「刪除」按鈕
- **Then** 確認 Dialog 顯示警告訊息：「此標籤目前已標記 N 位客戶，刪除後將同時移除所有客戶的此標籤。確定要刪除？」使用者確認後執行刪除（同時清除 customer_tag_assignments 中的對應記錄）

### AC-8：刪除取消
- **Given** 使用者開啟刪除確認 Dialog
- **When** 使用者點擊「取消」或關閉按鈕
- **Then** 取消刪除，標籤資料不變

### AC-9：標籤清單空狀態
- **Given** 系統中尚未建立任何全域標籤，且當前使用者也無自訂標籤
- **When** 使用者進入標籤管理頁面
- **Then** 顯示空狀態提示，並提供「建立標籤」快速入口按鈕

### AC-10：一般使用者嘗試透過 API 操作無權限的標籤
- **Given** 一般使用者嘗試透過 API 編輯或刪除全域標籤，或其他人的自訂標籤
- **When** API 請求送出
- **Then** 系統回傳 403 Forbidden，不執行任何變更

## Technical Notes

- 標籤採用**單層扁平結構**，不支援父標籤／子標籤階層；所有標籤在同一層級管理
- 標籤採用軟刪除（`deleted_at` 非 NULL 視為已刪除），保留歷史指派記錄的完整性
- 刪除標籤時，須同步刪除 `customer_tag_assignments` 中所有對應記錄（CASCADE 或應用層處理）
- 「已標記客戶數量」由 `customer_tag_assignments` 表 COUNT 聚合
- 權限控制邏輯：
  - **Admin**：可查看、編輯、刪除所有 `global` 及所有 `custom` 標籤
  - **一般使用者**：可查看所有 `global` 標籤（唯讀）、可查看/編輯/刪除自己的 `custom` 標籤（`owner_id = 當前使用者`）
- 一般使用者的「全域標籤」清單透過 API 查詢 `tag_type = 'global'` 的標籤
- 一般使用者的「我的標籤」清單透過 API 查詢 `tag_type = 'custom' AND owner_id = {currentUserId}` 的標籤

### API 端點

**標籤清單（一般使用者）**

- 端點：`GET /api/v1/c360/tags?page=1&pageSize=20`
- 後端依當前使用者身份自動過濾：一般使用者只能看到 `global` 標籤及自己的 `custom` 標籤
- Response：
```json
{
  "globalTags": [
    {
      "tagId": "uuid",
      "name": "VIP",
      "color": "#3B82F6",
      "tagType": "global",
      "description": "高價值客戶",
      "assignedCount": 42,
      "createdBy": "string",
      "createdAt": "ISO8601"
    }
  ],
  "myTags": [
    {
      "tagId": "uuid",
      "name": "跟進中",
      "color": "#F59E0B",
      "tagType": "custom",
      "ownerId": "uuid",
      "description": "本週需跟進",
      "assignedCount": 5,
      "createdBy": "string",
      "createdAt": "ISO8601"
    }
  ]
}
```

**標籤清單（Admin）**

- 端點：`GET /api/v1/c360/tags?page=1&pageSize=20`
- Admin 可見全部標籤（global + 所有 custom），Response 結構與一般使用者略有不同：
  - `myTags` 改為 `customTags`（代表系統所有自訂標籤，非僅 Admin 自己的）
  - `customTags` 中每筆標籤額外包含 `ownerName`（建立者姓名，格式：`"ownerName": "張業務"`）
  - 一般使用者視角的 `myTags` **不包含** `ownerName`（使用者僅看到自己的標籤，建立者即為本人，不需重複顯示）

**編輯標籤**

- 端點：`PATCH /api/v1/c360/tags/:tagId`
- Request Body：`{ "name": "string", "color": "#HEX", "description": "string" }`
- 錯誤（403 Forbidden）：無權限編輯

**刪除標籤**

- 端點：`DELETE /api/v1/c360/tags/:tagId`
- Response（200 OK）：`{ "deletedAssignments": 42 }`（回報同時清除的指派數量）
- 錯誤（403 Forbidden）：無權限刪除

## 測試案例

| # | 測試案例 | 預期結果 |
|---|---------|---------|
| 1 | 一般使用者進入標籤管理頁，系統有 3 個全域標籤、自己有 2 個自訂標籤 | 顯示兩區段：全域標籤 3 個（無操作按鈕）、我的標籤 2 個（有操作按鈕） |
| 2 | Admin 進入標籤管理頁 | 顯示兩區段：全域標籤（有操作按鈕）、自訂標籤（所有人的，含建立者姓名） |
| 3 | 一般使用者點擊全域標籤區段 | 無「編輯」「刪除」按鈕，無法操作 |
| 4 | 一般使用者編輯自己的自訂標籤「跟進中」→「積極跟進」 | 清單即時更新，Toast 通知顯示 |
| 5 | 一般使用者編輯自訂標籤名稱為自己另一個已存在的自訂標籤名稱 | 顯示重複名稱錯誤 |
| 6 | 一般使用者透過 API 嘗試刪除全域標籤 | 回傳 403 Forbidden |
| 7 | 一般使用者透過 API 嘗試刪除他人的自訂標籤 | 回傳 403 Forbidden |
| 8 | 刪除未指派任何客戶的自訂標籤 | 確認後標籤刪除，清單移除 |
| 9 | 刪除已指派 10 位客戶的全域標籤（Admin 操作） | 確認 Dialog 顯示警告「已標記 10 位客戶」，確認後刪除標籤與所有指派 |
| 10 | 刪除確認 Dialog 點擊取消 | 標籤保留，無任何變更 |
| 11 | 系統無任何標籤，進入標籤管理頁 | 顯示空狀態與「建立標籤」按鈕 |

## Definition of Done

- [ ] 標籤清單 API（GET /api/v1/c360/tags）實作完成，依角色回傳不同資料結構（globalTags + myTags / customTags）
- [ ] 編輯標籤 API（PATCH /api/v1/c360/tags/:tagId）實作完成，含 403 權限控制
- [ ] 刪除標籤 API（DELETE /api/v1/c360/tags/:tagId）實作完成（含 CASCADE 清除指派、403 權限控制）
- [ ] 前端標籤管理頁面實作完成（分區清單：全域標籤 / 我的標籤，編輯 Dialog，刪除確認 Dialog）
- [ ] 權限控制：一般使用者全域標籤唯讀；一般使用者僅可管理自己的自訂標籤
- [ ] Admin 可管理所有標籤（全域 + 所有人的自訂）
- [ ] 刪除有指派客戶的標籤警告訊息實作完成
- [ ] 軟刪除邏輯實作完成（deleted_at）
- [ ] 單元測試覆蓋率達標（> 80%）
