# US-063：管理標籤

> **Story ID**：US-063
> **Epic**：[E06 — Customer 360](epic-brief.md)
> **優先級**：Must Have
> **階段**：Phase 2
> **預估點數**：5

---

## User Story

**As a** 已登入的使用者（Admin 或 User）
**I want** 查看、編輯與刪除標籤
**So that** 我能維護標籤系統的整潔度，修正標籤名稱或顏色，移除不再使用的標籤

> **設計決策**：標籤採用**單層扁平結構，不支援階層（父標籤／子標籤）**。管理介面不提供階層操作（無「設定父標籤」、「移動至子分類」等功能）。（2026-04-02 業務確認）

---

## 驗收標準

### AC-1：查看標籤清單
- **Given** 使用者進入標籤管理頁面（Sidebar 中「Customer 360 > 標籤管理」，或客戶清單頁的「管理標籤」入口）
- **When** 頁面載入完成
- **Then** 顯示所有標籤的清單，每列包含：標籤色彩圓點、標籤名稱、標籤說明（選填）、已標記客戶數量、建立者、建立時間、操作按鈕（編輯、刪除）

### AC-2：編輯標籤
- **Given** 使用者在標籤清單點擊某標籤的「編輯」按鈕
- **When** 編輯 Dialog 開啟
- **Then** 預填現有的標籤名稱、顏色與說明，使用者修改後點擊「儲存」，系統更新標籤資料，清單即時反映變更，並顯示成功 Toast 通知

### AC-3：編輯標籤名稱重複驗證
- **Given** 使用者將標籤名稱修改為系統中已存在的另一個標籤名稱
- **When** 使用者點擊「儲存」
- **Then** 顯示驗證錯誤「標籤名稱已存在，請使用不同名稱」

### AC-4：刪除無客戶指派的標籤
- **Given** 某標籤目前未指派給任何客戶
- **When** 使用者點擊「刪除」按鈕，並在確認 Dialog 中點擊「確認刪除」
- **Then** 系統軟刪除該標籤，從清單中移除，顯示成功 Toast 通知「標籤已刪除」

### AC-5：刪除已有客戶指派的標籤
- **Given** 某標籤已指派給至少 1 位客戶
- **When** 使用者點擊「刪除」按鈕
- **Then** 確認 Dialog 顯示警告訊息：「此標籤目前已標記 N 位客戶，刪除後將同時移除所有客戶的此標籤。確定要刪除？」使用者確認後執行刪除（同時清除 customer_tag_assignments 中的對應記錄）

### AC-6：刪除取消
- **Given** 使用者開啟刪除確認 Dialog
- **When** 使用者點擊「取消」或關閉按鈕
- **Then** 取消刪除，標籤資料不變

### AC-7：標籤清單空狀態
- **Given** 系統中尚未建立任何標籤
- **When** 使用者進入標籤管理頁面
- **Then** 顯示空狀態提示，並提供「建立標籤」快速入口按鈕

## Technical Notes

- 標籤採用**單層扁平結構**，不支援父標籤／子標籤階層；所有標籤在同一層級管理
- 標籤採用軟刪除（`deleted_at` 非 NULL 視為已刪除），保留歷史指派記錄的完整性
- 刪除標籤時，須同步刪除 `customer_tag_assignments` 中所有對應記錄（CASCADE 或應用層處理）
- 「已標記客戶數量」由 `customer_tag_assignments` 表 COUNT 聚合，可作為計算欄位或定期更新的快取值
- Phase 2 暫不區分自建標籤（僅能管理自己建立的）與全域標籤（可管理所有標籤）；Admin 可管理所有標籤，User 僅可管理自己建立的標籤

### API 端點

**標籤清單**

- 端點：`GET /api/v1/c360/tags?page=1&pageSize=20`
- Response：
```json
{
  "data": [
    {
      "tagId": "uuid",
      "name": "VIP",
      "color": "#3B82F6",
      "description": "高價值客戶",
      "assignedCount": 42,
      "createdBy": "string",
      "createdAt": "ISO8601"
    }
  ],
  "pagination": { "page": 1, "pageSize": 20, "total": 0, "totalPages": 0 }
}
```

**編輯標籤**

- 端點：`PATCH /api/v1/c360/tags/:tagId`
- Request Body：`{ "name": "string", "color": "#HEX", "description": "string" }`

**刪除標籤**

- 端點：`DELETE /api/v1/c360/tags/:tagId`
- Response（200 OK）：`{ "deletedAssignments": 42 }`（回報同時清除的指派數量）

## 測試案例

| # | 測試案例 | 預期結果 |
|---|---------|---------|
| 1 | 系統有 3 個標籤，進入標籤管理頁 | 顯示 3 個標籤，含已標記客戶數 |
| 2 | 編輯標籤名稱為「Super VIP」並儲存 | 清單即時更新，Toast 通知顯示 |
| 3 | 編輯名稱為已存在的另一標籤名稱 | 顯示重複名稱錯誤 |
| 4 | 刪除未指派任何客戶的標籤 | 確認後標籤刪除，清單移除 |
| 5 | 刪除已指派 10 位客戶的標籤 | 確認 Dialog 顯示警告「已標記 10 位客戶」，確認後刪除標籤與所有指派 |
| 6 | 刪除確認 Dialog 點擊取消 | 標籤保留，無任何變更 |
| 7 | 系統無標籤，進入標籤管理頁 | 顯示空狀態與「建立標籤」按鈕 |
| 8 | User 嘗試刪除他人建立的標籤 | 顯示 403 Forbidden 錯誤 |

- [ ] 軟刪除邏輯實作完成（deleted_at）
