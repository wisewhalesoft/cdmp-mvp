# US-053：節點 Inspector Panel 欄位 Diff

> **Story ID**：US-053
> **Epic**：[E05 — ETL Pipeline 管理](epic-brief.md)
> **優先級**：Should Have
> **階段**：Phase 1（MVP）
> **預估點數**：5

---

## User Story

**As a** Admin（ETL 設計者）
**I want** 點擊節點後，在右側屬性面板中看到「輸入欄位 → 轉換 → 輸出欄位」的結構化 Diff 分頁
**So that** 我能在設定節點時立即驗證欄位轉換是否符合預期，減少因欄位名稱錯誤或欄位遺失導致的 Pipeline 執行失敗

---

## 背景說明

US-042 已在右側屬性面板提供節點設定表單（AC-5）。本 Story 在現有面板基礎上新增「欄位」分頁，以輸入/輸出欄位列表搭配 Diff 標記，讓設計者能直觀審查每個節點的欄位轉換結果，無需執行 Pipeline 即可發現問題。

---

## 驗收標準

### AC-1：屬性面板新增「欄位」分頁

- **Given** Admin 點擊任意一個節點，右側屬性面板已開啟
- **When** 面板載入完成
- **Then** 面板頂部顯示分頁切換列，包含「設定」與「欄位」兩個分頁；預設停留在「設定」分頁，不改變現有設定表單行為

### AC-2：切換至「欄位」分頁顯示輸入欄位列表

- **Given** Admin 在屬性面板切換至「欄位」分頁，該節點的上游欄位可被計算
- **When** 分頁內容渲染完成
- **Then** 面板顯示「輸入欄位」區塊，列出所有輸入欄位名稱（每列顯示：欄位名稱、資料型別）

### AC-3：切換至「欄位」分頁顯示輸出欄位列表

- **Given** Admin 在屬性面板切換至「欄位」分頁，該節點的設定已完整
- **When** 分頁內容渲染完成
- **Then** 面板顯示「輸出欄位」區塊，列出所有輸出欄位名稱（每列顯示：欄位名稱、資料型別）

### AC-4：新增欄位以綠色標記

- **Given** 節點類型為 `derived_field`，設定了 2 條衍生欄位運算式，輸出欄位中含有 2 個輸入欄位列表中不存在的欄位
- **When** Admin 切換至「欄位」分頁
- **Then** 輸出欄位列表中，該 2 個新增欄位顯示綠色背景或前綴 `+` 標記

### AC-5：移除欄位以紅色標記

- **Given** 節點類型為 `field_mapping`，`dropUnmapped=true`，有 5 個輸入欄位未被映射而被移除
- **When** Admin 切換至「欄位」分頁
- **Then** 面板在「輸出欄位」區塊上方（或獨立的「已移除」區塊）顯示該 5 個欄位，以紅色前綴 `-` 標記

### AC-6：保留欄位以中性色顯示

- **Given** 節點類型為 `dedup`，輸入 15 欄，輸出 15 欄（透傳）
- **When** Admin 切換至「欄位」分頁
- **Then** 輸出欄位列表的 15 個欄位皆顯示為中性色（無特殊標記）

### AC-7：節點設定不完整時顯示提示

- **Given** Admin 點擊一個尚未選擇資料來源的 `raw_data_extract` 節點，切換至「欄位」分頁
- **When** 面板渲染完成
- **Then** 面板顯示提示訊息「請先完成節點設定以檢視欄位資訊」，不顯示空白列表

### AC-8：節點設定更新後 Diff 即時刷新

- **Given** Admin 在「設定」分頁修改 `field_mapping` 節點的映射規則並儲存
- **When** Admin 切換回「欄位」分頁
- **Then** 欄位 Diff 內容反映最新的映射設定，顯示更新後的輸入/輸出欄位與差異標記

## 商業規則

| 規則編號 | 說明 |
|----------|------|
| BR-1 | 「欄位」分頁的計算資料來源與 US-052 Badge 相同，均使用 `computeNodeOutputColumns()` |
| BR-2 | 「設定」分頁的現有功能不得受本 Story 影響，預設分頁維持「設定」 |
| BR-3 | 欄位列表中的資料型別資訊若來源不可知（上游未設定），顯示 `-`（未知）而非空白 |
| BR-4 | 本分頁僅提供唯讀展示，不可在此分頁直接編輯欄位設定 |

---

## Diff 標記規格

| 狀態 | 標記符號 | 顏色 | 適用節點類型 |
|------|---------|------|------------|
| 新增 | `+` 前綴 | 綠色（success） | `derived_field` |
| 移除 | `-` 前綴 | 紅色（danger） | `field_mapping`（dropUnmapped=true） |
| 保留 | 無符號 | 中性色 | 所有透傳型節點 |
| 重命名 | `→` 符號 | 藍色（info） | `field_mapping`（有別名映射） |

## Technical Notes

- 本 Story 為前端功能，無需後端 API 變更
- 建議使用 React 的 `useMemo` 在 `nodes`/`edges` state 變更時重新計算 Diff，避免每次 render 重算
- 輸入欄位列表 = 上游節點的 `computeNodeOutputColumns()` 結果
- 輸出欄位列表 = 本節點的 `computeNodeOutputColumns()` 結果
- Diff 計算邏輯（純前端）：
  - 新增 = 存在於輸出但不存在於輸入的欄位（by 欄位名稱）
  - 移除 = 存在於輸入但不存在於輸出的欄位（by 欄位名稱）
  - 保留 = 同時存在於輸入與輸出的欄位

## 測試案例

### TC-053-01：屬性面板顯示「設定」與「欄位」分頁

- **Given** 畫布上有任意節點
- **When** Admin 點擊節點
- **Then** 右側面板顯示「設定」與「欄位」兩個分頁，預設停在「設定」

### TC-053-02：derived_field 節點欄位新增標記

- **Given** derived_field 節點，輸入 10 欄，新增 3 條衍生欄位
- **When** 切換至「欄位」分頁
- **Then** 輸出欄位列表中，3 個衍生欄位顯示綠色 `+` 標記，其餘 10 欄無標記

### TC-053-03：field_mapping dropUnmapped=true 欄位移除標記

- **Given** field_mapping 節點，輸入 15 欄，僅映射 8 欄，`dropUnmapped=true`
- **When** 切換至「欄位」分頁
- **Then** 顯示 7 個移除欄位（紅色 `-` 標記），輸出欄位列表顯示 8 欄（無標記）

### TC-053-04：節點未設定時顯示提示訊息

- **Given** raw_data_extract 節點，尚未選擇資料來源
- **When** Admin 切換至「欄位」分頁
- **Then** 顯示「請先完成節點設定以檢視欄位資訊」，不顯示空白列表

### TC-053-05：切換至「設定」分頁後現有表單功能正常

- **Given** Admin 進入「欄位」分頁後
- **When** 切換回「設定」分頁
- **Then** 設定表單正常顯示，所有輸入欄位與值保持不變

### TC-053-06：設定變更後欄位分頁即時刷新

- **Given** Admin 在「設定」分頁新增一條 derived_field 規則
- **When** 儲存設定後切換至「欄位」分頁
- **Then** 輸出欄位列表即時反映新增的欄位
