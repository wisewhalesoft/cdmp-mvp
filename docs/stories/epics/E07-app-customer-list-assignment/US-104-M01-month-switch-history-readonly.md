# US-104：月份切換與歷史月份唯讀

> **Story ID**：US-104
> **Epic**：[E07 — 客戶名單分派](epic-brief.md)
> **模組**：M01 名單定義
> **優先級**：Must Have
> **階段**：Phase 1（MVP）
> **預估點數**：3

---

## User Story

**As a** 部長（Director）或 Admin 或 處長（Section Chief）
**I want** 在 E07 名單定義頁面切換作業月份，查看過去或未來月份的名單狀態，並確保歷史月份的名單呈現唯讀
**So that** 可追溯過去月份的名單配置，同時防止誤改已執行的歷史記錄

---

## 背景說明

E07 月跑是以「作業年月（PROJECT_WORKYM）」為週期運作。使用者需要能在 M01 頁面切換作業年月，查看不同月份的名單清單。

**月份範圍規則（確認）**：
- **最大可切換範圍**：前 1 年 ~ 後 1 年（共 25 個月份）
- **歷史月份**（< 目前作業月份）：所有名單定義呈現唯讀；停用、編輯、新增等操作均不可用
- **目前作業月份**：完整操作（依角色與階段限制）
- **未來月份**（> 目前作業月份）：允許預先建立草稿名單（by 部長 / Admin）

**「目前作業月份」定義（2026-05-15 OQ-C-01 確認）**：每月 **1 號 0:00** 自動切換至該月為目前作業月份（例：2026-06-01 00:00 起，作業月份切換為 202606）。後端直接依此規則計算，前端讀取後端提供的 `current_work_ym` 值，不自行計算。若後端存在配置項可覆蓋此規則，以配置值為準；否則預設寫死為每月 1 號切換。

> **[待 spec-writer 評估]**：是否需要在 application config 中新增 `WORK_YM_SWITCH_DAY` 配置項（預設值 = 1）？建議由 spec-writer 依實作慣例決定，本 Story 預設行為為硬編碼每月 1 號。

## 驗收標準

### AC-1：月份切換器顯示範圍

- **Given** 任意擁有 E07 存取權限的使用者進入 M01 名單定義頁
- **When** 頁面載入
- **Then** 頂部顯示月份切換器，可選範圍為目前作業月份前後各 12 個月（共 25 個月）
- **And** 切換器預設顯示目前作業月份
- **And** 超出 25 個月範圍的月份不可選取

### AC-2：歷史月份名單呈現唯讀

- **Given** 使用者選擇**過去月份**（< 目前作業月份）
- **When** 名單定義清單或詳情頁顯示該月份的名單
- **Then** 所有名單的操作按鈕（新增、編輯、停用、推進至下一階段、觸發月跑）均**不顯示**或顯示為停用狀態
- **And** 頁面頂部顯示提示條：「歷史月份資料為唯讀，不可修改」
- **And** 若透過 API 嘗試對歷史月份名單進行寫入操作，後端回 422（「歷史月份資料不可修改」）

### AC-3：目前作業月份判斷規則（OQ-C-01）

- **Given** 後端計算「目前作業月份」
- **When** 系統時鐘在當月 1 號 0:00（含）之後、下月 1 號 0:00 之前
- **Then** `current_work_ym` = 本月 YYYYMM（例：2026-06-15 → `202606`）
- **And** 前端透過 API 取得 `current_work_ym`，不自行計算
- **And** 若後端存在覆蓋配置，以配置值為準

### AC-4（原 AC-3）：目前作業月份保有完整操作能力

- **Given** 使用者選擇目前作業月份（或切換回目前月份）
- **When** 名單定義清單或詳情頁顯示
- **Then** 所有對應角色與階段的操作按鈕正常顯示
- **And** 不顯示「歷史月份唯讀」提示條

### AC-5（原 AC-4）：未來月份允許預先建立草稿（部長 / Admin 限定）

- **Given** 部長或 Admin 選擇**未來月份**（> 目前作業月份）
- **When** 進入 M01 名單定義頁
- **Then** 顯示該未來月份的名單清單（如已有預先建立的草稿）
- **And** 部長或 Admin 可在未來月份新建草稿名單（限草稿阶段操作）
- **And** 其他操作（推進、停用）依正常草稿階段邏輯執行

### AC-6（原 AC-5）：月份切換後 URL 或狀態更新

- **Given** 使用者切換至不同月份
- **When** 月份切換器選擇變更
- **Then** 頁面內容刷新為選定月份的名單清單
- **And** URL 或頁面狀態更新（例如 query param `?ym=202506`），使用者可直接分享連結給他人查看特定月份

## 技術備註

- 月份切換的資料過濾：後端依 `PROJECT_WORKYM` 過濾 `ob_list_definition` 表
- **「目前作業月份」計算規則（OQ-C-01 決議）**：後端依系統時鐘判斷，每月 **1 號 0:00** 切換至該月（即 `current_work_ym = YYYYMM of today`）。前端讀取後端提供的 `current_work_ym` 值，不自行計算。
- 歷史月份唯讀的後端實作：在各寫入 API 的 Guard 層加入「請求的 `project_workym` < `current_work_ym`」時回 422（「歷史月份資料不可修改」）；目前月份與未來月份不受此限
- 月份切換器 UI 建議：下拉選單或年月選擇器，顯示格式「YYYY年MM月」

## 測試案例

### TC-104-01：月份切換器預設顯示目前作業月份

- **Given**：系統當前作業月份為 202506
- **When**：部長進入 M01 名單定義頁
- **Then**：月份切換器顯示「2025年06月」；名單列表顯示 PROJECT_WORKYM = '202506' 的資料

### TC-104-02：切換至歷史月份名單呈現唯讀

- **Given**：系統當前作業月份為 202506；部長選擇月份切換至 202504
- **When**：頁面刷新顯示 202504 的名單
- **Then**：所有名單無「新增」「編輯」「停用」等按鈕；頁面頂部顯示「歷史月份資料為唯讀」提示

### TC-104-03：API 嘗試寫入歷史月份被拒

- **Given**：系統當前作業月份為 202506
- **When**：部長嘗試呼叫 POST /api/v1/list-definitions（body 含 project_workym = '202504'）
- **Then**：後端回 422，錯誤訊息「歷史月份資料不可修改」

### TC-104-04：月份範圍邊界驗證

- **Given**：系統當前作業月份為 202506
- **When**：月份切換器顯示可選範圍
- **Then**：可選最早月份為 202406（前 12 個月）；可選最晚月份為 202606（後 12 個月）；超出範圍月份不可選
