# US-182：樞紐分析頁籤 UX 精修 — 職稱／新人標註／總計欄置前／工作天模式（F116 v1.1）

## User Story

**As a** 業務部長 / 業務處長
**I want** 在「客戶名單分派 > 執行歷史 > 檢視快照 > 樞紐分析」頁籤中，(1) 員編列能同時看到職稱並標註新進人員、(2) 總計欄排在最左側方便閱讀、(3) 除了「整月」計數/佔比外，也能切換看「該月工作日 1 天要撥打的名單數量」
**So that** 我能更快辨識人員資歷（新人 vs 資深）、更符合閱讀習慣地掌握總量，並直接看出每人每個工作天的實際撥打負荷，不必自行拿月計數除以工作日數手動換算

---

## 背景說明

[F116](../../../specs/features/F116-snapshot-pivot-analysis.md)（2026-07-14 已上線）於快照詳情新增第 4 頁籤「樞紐分析」，以「部門名稱 → 員編（+姓名）」為列、「名單代號」為欄、「案號計數」為值呈現交叉表，並提供計數/佔比 toggle、展開/收合、sticky 首欄與總計行/列。

現況（v1.0）：
1. 員編列僅顯示「員編 + 姓名」，未顯示職稱，也無新進人員標註。
2. 「總計」欄位於表格**最右側**（`ob_monthly_run_result` GROUP BY 聚合後 `listNos` 升冪排列 + 總計欄殿後）。
3. 值只有「計數 / 佔比」兩種模式，皆對應「整月」累計；無法看出單一工作天的撥打負荷。

本 story 為使用者提出的三項 UX 改善需求，均為對既有樞紐分析頁籤的**精修**，不新增頁籤、不改變既有導覽入口。

---

## 需求一：員編列補顯示職稱＋新進人員標註

### AC-1：員編列顯示「員編－姓名－職稱」

- **Given** 使用者於快照詳情「樞紐分析」頁籤，已展開任一部門列
- **When** 檢視該部門下的員編列
- **Then** 每一列除既有「員編＋姓名」外，另顯示**職稱**，來源為 `ob_emphire.JFUN_NM`（非 `TITLE_NAME`）
- **And** 三者的呈現順序與串接方式為「員編－姓名－職稱」

### AC-2：未滿三個月標註「新人」

> 基準日與邊界定義已由使用者裁定（[[OQ-1]] / [[OQ-2]]，RESOLVED 2026-08-13），本 AC 為確定條文：

- **基準日** = 該 run `project_workym` 的**月初**（當月 1 日）。例：`project_workym = 202607` → 基準日 = 2026-07-01。快照為歷史資料，此判定固定不隨檢視時間漂移。
- **判定式** = `HIRE_DATE > 基準日 − 3 個月` 才是新人；恰好滿 3 個月**不**算新人（嚴格未滿）。例：基準日 2026-07-01 → 門檻 2026-04-01；`HIRE_DATE = 2026-04-01` 不是新人，`HIRE_DATE = 2026-04-02` 是新人。
- **Given** 樞紐分析頁籤某員編列對應之 `ob_emphire.HIRE_DATE` 存在
- **When** 依上述判定式計算，該員編到職日晚於門檻日（未滿三個月）
- **Then** 該員編列顯示「新人」標註
- **And** 已滿三個月（或以上）者不顯示該標註

### AC-3：職稱／新人標註的邊界情境

- **Given** 員編對應之 `ob_emphire.JFUN_NM` 為 NULL 或空字串
- **Then** 職稱欄位以空白／預留 placeholder 呈現（不得整列消失、不得報錯）
- **Given** 員編對應之 `ob_emphire.HIRE_DATE` 為 NULL
- **Then** 不顯示「新人」標註（無法判定到職資歷，不臆測）
- **Given** 員編已離職（`ob_emphire.RESIGN_DATE` 有值，依 [[feedback_emphire_active_resign_sentinel]] 之在職判斷規則屬「非在職」）但該 run 的分派結果中仍有其筆數
- **Then** 該員編列仍需正常顯示職稱／新人標註（樞紐分析呈現的是**歷史 run 快照的分派事實**，不因員工目前在職狀態被過濾或特殊處理）
- **Given** 部門或員編依既有規則歸組為「(空白)」
- **Then** 「(空白)」列不顯示職稱與新人標註（無對應 `ob_emphire` 主檔資料）

---

## 需求二：總計欄移至最前（最左）

### AC-4：總計欄改列於名單代號欄位之前

- **Given** 使用者於快照詳情「樞紐分析」頁籤
- **When** 檢視交叉表欄軸
- **Then** 「總計」欄改為表格**最左側**（緊接列標籤欄之後、名單代號欄位之前），取代現行「最右側」位置
- **And** 各名單代號欄仍維持既有升冪排序
- **And** 總計欄之數值語意（部門/員編/大表總計）不變，僅欄位順序調整
- **And**（[[OQ-8]] RESOLVED 2026-08-13）本次**僅**移動總計**欄**；總計**列**（表格最下方一列）維持不變，不隨本 AC 調整位置

## 需求三：新增「整月 / 工作天」維度

### AC-5：新增「整月／工作天」切換，顯示該月工作日 1 天的撥打量

> 工作日來源、計算語意、精度、與計數/佔比的互動關係已由使用者裁定（[[OQ-4]] / [[OQ-5]] / [[OQ-6]] / [[OQ-7]]，RESOLVED 2026-08-13），本 AC 為確定條文：

- **工作日來源** = `ob_calendar.rest_flg = '0'`（沿用既有 `weekday` CalendarSource，即現行 Stage0 每日試算同一套規則，排除週末＋國定假日）；月份基準 = 該 run 的 `project_workym`。
- **計算公式** = `該格「整月」計數 ÷ 該月工作日數`，再**無條件進位（ceil）到整數**（不採 `assignday` 逐日實際分佈）。例：100 ÷ 21 = 4.76 → 顯示 `5`。
- **與計數/佔比的組合** = 「工作天」模式下**停用「佔比」**；合法組合僅 3 種：`整月-計數`／`整月-佔比`／`工作天-計數`。
- **Given** 使用者於快照詳情「樞紐分析」頁籤，且目前顯示模式為「整月-佔比」
- **When** 切換至「工作天」模式
- **Then** 值同時自動回落為「計數」語意（即進入 `工作天-計數`），「佔比」切換按鈕在工作天模式下呈 disabled 狀態
- **And** 每一格數值依上述公式計算並以整數呈現
- **And** 切回「整月」模式時，恢復現行（v1.0）計數／佔比顯示與可切換狀態

### AC-6：工作天模式的邊界情境

- **Given** 目標 `project_workym` 當月工作日數（依 `ob_calendar.rest_flg='0'` 計算）為 0（例如 `ob_calendar` 缺該月資料等極端情境）
- **When** 使用者切換至「工作天」模式
- **Then** 全表數值改顯示為 `-`（非計算值），不得顯示 `NaN`/`Infinity`、不得除以零、不得中斷頁面渲染
- **And** 工具列顯示明確提示訊息，告知「本月無工作日資料，無法計算」（確切措辭由 spec-writer / ui-ux-designer 定案）
- **Given** 樞紐分析頁籤既有「(空白)」部門／員編分組
- **Then** 工作天模式下「(空白)」分組的換算邏輯與一般分組一致，不特殊處理；其職稱／新人標註仍依 AC-3 結論一律不顯示
- **Given** 使用者在「工作天」模式下操作既有「全部展開／全部收合」
- **Then** 展開/收合行為不受影響，維持 v1.0 既有邏輯

## 相容性影響（對既有 F116 v1.0 行為）

| 既有行為 | 本次影響 |

| 總計行（表格最下方一列） | 「總計欄」（縱向、最右→最左）與「總計列」（橫向、最下）為兩個不同軸；[[OQ-8]] RESOLVED：本次**只移動總計欄**（最右→最左），**總計列維持在表格最下方不動**，變動最小化 |
| 處長轄區 scope（`scopeByCreator`，只回轄區內 emplid，不回 403） | 不變；職稱／新人標註／工作天換算僅套用於既有 scoped 後的資料列，不擴大或縮小可見範圍 |

| 運算歸屬（前端換算 vs 後端下推） | 現行佔比為前端換算；工作天換算之運算歸屬（前端 or 後端）由 system-architect 決定，本 story 只定義使用者可見結果 |

## Open Questions（RESOLVED — 2026-08-13 人工閘門裁定）

> 以下 8 題已由使用者於人工閘門全數裁定；結論已回寫至 AC-2 / AC-4 / AC-5 / AC-6 / 相容性影響表對應章節。本節保留原始選項供追溯，並標記最終結論。

### OQ-1：「新人」判定的基準日是什麼？ — **RESOLVED（使用者裁定 2026-08-13）**

- **結論**：採原選項 B — 基準日 = 該 run `project_workym`（作業月）**月初**（當月 1 日）。快照為歷史資料，標註須固定不隨檢視時間漂移。
- 原始選項：A. 系統當日／B. `project_workym` 月初／C. `project_workym` 月底／D. run 實際執行日。

### OQ-2：「未滿三個月」的邊界如何定義？ — **RESOLVED（協調者以合理預設裁定）**

- **結論**：採原選項 A — 嚴格「未滿」。判定式：`HIRE_DATE > 基準日 − 3 個月` 才是新人；恰好滿 3 個月**不**算新人。`HIRE_DATE` 為 NULL → 一律不標註。例：`project_workym=202607` → 基準日 2026-07-01，門檻 2026-04-01；2026-04-01 到職者不是新人，2026-04-02 到職者是新人。
- 原始選項：A. `> 基準日` 才算新人（恰滿不算）／B. `≥ 基準日` 也算新人（恰滿仍算）。

### OQ-3：「員編－姓名－職稱」的分隔／缺值呈現，是否需要在 story 層先定調？ — **RESOLVED（使用者裁定 2026-08-13）**

- **結論**：不在 story 層定調，完全交 ui-ux-designer 決定。分隔符號、職稱缺值呈現、「新人」標籤樣式（badge/文字）屬純視覺決策，**authority = ui-ux-designer 之 `prototypes/35-snapshot-detail.html`**。
- 原始選項：A. 純視覺全交 ui-ux-designer／B. story 層先定調基本規則。

### OQ-4：工作天模式的「工作日」來源與月份基準？ — **RESOLVED（使用者裁定 2026-08-13）**

- **結論**：採原選項 A — 沿用既有 `ob_calendar.rest_flg = '0'`（即專案既有 `weekday` CalendarSource，涵蓋國定假日，與現行 Stage0 每日試算同一套規則）；月份基準 = 該 run 的 `project_workym`。
- 原始選項：A. `ob_calendar rest_flg='0'`／B. 純週一～週五。

### OQ-5：工作天模式的計算語意是什麼？ — **RESOLVED（使用者裁定 2026-08-13）**

- **結論**：採原選項 A — 平均攤提：`該格整月計數 ÷ 該月工作日數`。**不**採 `assignday` 逐日實際分佈。
- 原始選項：A. 平均攤提／B. 依 `assignday` 逐日實際分佈取平均/尖峰。

### OQ-6：工作天模式的呈現精度？ — **RESOLVED（使用者裁定 2026-08-13）**

- **結論**：採原選項 C — 無條件進位到整數（ceil）。例：100 ÷ 21 = 4.76 → 顯示 `5`。
- 原始選項：A. 四捨五入到整數／B. 保留 1 位小數／C. 無條件進位到整數。

### OQ-7：「整月/工作天」是否與既有「計數/佔比」構成獨立的第二維度？ — **RESOLVED（使用者裁定 2026-08-13）**

- **結論**：採原選項 B — 「工作天」模式下停用「佔比」。合法組合僅 3 種：`整月-計數`／`整月-佔比`／`工作天-計數`；切到工作天時佔比按鈕 disabled 並自動回落計數。
- 原始選項：A. 完全獨立 2×2（含 `工作天-佔比`）／B. 工作天模式停用佔比（3 種組合）／C. 三選一互斥。

### OQ-8：「總計欄移到最前面」是否連帶要求「總計列」也移到最上面？ — **RESOLVED（使用者裁定 2026-08-13）**

- **結論**：採原選項 A — 僅移動總計**欄**（縱軸，最右→最左）；總計**列**（橫軸，最下方）維持不變。嚴格照使用者原句（「橫向的總計欄」），變動最小化。
- 原始選項：A. 只移總計欄，總計列不變／B. 欄列一併移到最前/最上。
