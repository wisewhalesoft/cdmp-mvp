# US-174：CARD_LEVEL「預估各等級分佈」改為抽樣估算並修正錯誤顯示

> **Story ID**：US-174
> **Epic**：[E07 — 客戶名單分派](epic-brief.md)
> **模組**：M02 計分設定（Tab 4 — CARD_LEVEL 門檻，擴充 US-074 AC-3）
> **優先級**：Must Have（生產環境現行功能故障，非新功能）
> **階段**：Phase 1（MVP）
> **預估點數**：5
> **版本**：v1（2026-07-11 — 新增；修正 US-074 AC-3「預估各等級分佈」面板在生產環境顯示空白之缺陷）

---

## User Story

**As a** 業務主管（部長 / 處長，唯讀）
**I want** 在 Tab 4（CARD_LEVEL 門檻）調整門檻草稿時，於合理時間內看到「預估各等級分佈」的估算結果（而非長時間無回應後畫面空白）
**So that** 我能即時掌握門檻調整對各等級人數分佈的影響，安心完成門檻設定，不必懷疑系統是否故障

---

## 背景說明（問題根因，team lead 已於執行環境確認）

US-074 AC-3 原規格為「以目前 Pool 資料套用新門檻計算，可非即時，允許最多 1 分鐘快取」。實際落地後，後端 `GET /api/v1/assignment/scoring/card-levels/preview`（F055 §5.2）對 `ob_pool_data` 全表（1,679,489 筆）即時套用完整 Stage 2 計分算式重新計分，實測 CARD_TYPE=E 情境耗時 **224.6 秒**，遠超前端請求逾時；同時前端 `scoring-config-page.tsx`（約 L1499）以 `catch { setPreview(null) }` 靜默吞掉逾時 / 錯誤，導致面板直接顯示空白、無任何錯誤提示，業務主管無從得知是系統故障還是資料本身沒有分佈。

本 Story 為 US-074 AC-3 的修正與升級：以**抽樣估算**取代全量即時計分（達成次秒級回應），並修正前端錯誤吞噬問題（讓失敗狀態可見、可重試），同時原 AC-3「允許最多 1 分鐘快取」之語意由本 Story 之次秒級抽樣估算取代（不再需要快取）。

本 Story 與 US-175、US-176 共用同一套「抽樣估算」產品邏輯（見下方 D1 定義），三者互為對照，實作時應一致。

---

## 驗收標準

### AC-1：抽樣估算取代全量即時計分（效能）

- **Given** 業務主管在 Tab 4 修改任一等級的 `score_s` / `score_e`（尚未儲存）
- **When** 系統計算「預估各等級分佈」
- **Then** 估算計算方式改為：對 `ob_pool_data` 取一組**固定筆數的隨機樣本**，套用草稿門檻分級後，依樣本佔比**放大推算至母體總筆數**，不再對全表即時計分
- **And** 樣本筆數為固定值（非動態依當下總筆數變動），實際樣本大小由 spec-writer / system-architect 依統計精度與效能兩者權衡決定，本 Story 不指定數值，僅要求「固定筆數」
- **And** API 回應時間目標為**次秒級（< 1 秒）**，取代原全量計分動輒逾百秒的行為

### AC-2：估算結果須可重現（相同輸入 → 相同輸出）

- **Given** 業務主管以相同的 CARD_TYPE 與相同的門檻草稿值，於短時間內重複觸發預覽（例如反覆切換焦點導致多次呼叫）
- **When** 系統多次計算估算分佈
- **Then** 兩次的估算數字須完全一致（抽樣須使用**可重現的固定種子**，不得每次隨機出不同結果），避免業務主管誤以為系統數字不穩定 / 不可信
- **And** 僅當草稿門檻值或 Pool 資料本身變動時，估算數字才允許改變

### AC-3：估算結果明確標示為「約略值」

- **Given** 面板顯示「預估各等級分佈」
- **When** 呈現各等級人數
- **Then** UI 上須有明顯文字標示本結果為**抽樣估算值**（如「約」字樣或「基於樣本估算」註記），不得讓業務主管誤認為是精確全量計數
- **And** 具體文案措辭由 ui-ux-designer / spec-writer 決定，本 AC 僅要求「必須有估算標示」這項行為契約

### AC-4：估算失敗時明確顯示錯誤狀態（修正靜默吞噬缺陷）

- **Given** 估算 API 呼叫失敗（逾時、5xx、網路錯誤等任何原因）
- **When** 前端接收到失敗結果
- **Then** 面板**不得直接變回空白**，須顯示明確的錯誤 / 無法載入狀態提示（例如「預估分佈暫時無法取得，請稍後再試」），並提供可重試的操作（如「重新整理」按鈕或自動重試）
- **And** 此錯誤狀態須與「載入中」「已顯示估算結果」在視覺上可清楚區分（三態：載入中 / 顯示估算 / 錯誤重試）
- **And** 修正現行 `catch { setPreview(null) }` 吞噬錯誤而不告知使用者的行為

### AC-5：既有範圍鎖與角色權限不變

- **Given** 業務主管在 Tab 4 操作預覽功能
- **When** 呼叫預覽估算
- **Then** 沿用 US-074 AC-4 之 CARD_TYPE 範圍鎖（估算僅套用 Tab 1 選中之 CARD_TYPE）
- **And** 沿用既有 GET 端點 RBAC（部長 / 處長 / Admin 皆可讀取預覽），本 Story 不變更權限模型

### AC-6：不新增路由 / Sidebar 入口

- **Given** 本功能為既有 `/assignment/scoring` 頁面 Tab 4 內的既有面板修正
- **When** 功能上線
- **Then** 不新增任何路由或 Sidebar 導覽項目，UI 位置與現行 Tab 4「預估各等級分佈」面板位置一致

## 技術備註

- **根因**（team lead 已於執行環境量測確認）：`GET /api/v1/assignment/scoring/card-levels/preview`（F055 §5.2）對 `ob_pool_data` 全表即時套用完整 Stage 2 計分表達式，CARD_TYPE=E 實測 224.6 秒；前端 `apps/web/src/pages/assignment/scoring-config-page.tsx` 約 L1499 `catch { setPreview(null) }` 靜默吞錯
- API 路徑沿用既有 `GET /api/v1/assignment/scoring/card-levels/preview`（F055 §5.2），本 Story 僅要求變更其計算方法與效能特性；Response schema 是否需擴充欄位（如 `isEstimate` / `sampleSize` 等中介資訊供前端顯示 AC-3 標示）由 spec-writer 決定
- 抽樣演算法、樣本筆數、種子產生機制、放大推算公式等實作細節，由 system-architect / spec-writer 依 D1 決策訂定，本 Story 僅定義產品行為契約
- 本 Story 取代 US-074 AC-3 原「可非即時，允許最多 1 分鐘快取」之描述；spec-writer 更新 F055 時請一併修訂 AC-3 措辭

> **[產品決策 D1，team lead 已拍板，不可再議]**：估算採 `ob_pool_data` 之**固定筆數隨機樣本** + **可重現（repeatable）種子**，依樣本結果放大推算至母體總數；結果一律標示為估算值（約/估算字樣）；效能目標為次秒級。本決策同時適用於 US-174（本 Story）與 US-175。

## 測試案例

### TC-174-01：抽樣估算於次秒級回應

- **Given**：Tab 1 選中 CARD_TYPE = 'E'；`ob_pool_data` 現有 1,679,489 筆
- **When**：業務主管修改門檻草稿，觸發預覽估算
- **Then**：估算結果於 1 秒內回應完成（相較修正前 224.6 秒）

### TC-174-02：相同輸入重複呼叫結果一致

- **Given**：CARD_TYPE = 'H'，門檻草稿值固定不變
- **When**：短時間內重複觸發兩次預覽估算
- **Then**：兩次回傳的各等級人數完全相同

### TC-174-03：估算結果標示為約值

- **Given**：預覽面板顯示估算分佈
- **When**：業務主管檢視面板
- **Then**：畫面上有明確文字標示（如「約」/「估算」）而非呈現為精確計數

### TC-174-04：估算失敗顯示錯誤狀態並可重試

- **Given**：估算 API 因逾時或錯誤回傳失敗
- **When**：前端接收失敗回應
- **Then**：面板顯示明確錯誤提示與重試操作，不直接變回空白

### TC-174-05：CARD_TYPE 範圍鎖與角色權限不受影響

- **Given**：Tab 1 選中 'H'，登入者為處長角色
- **When**：處長檢視 Tab 4 預覽面板
- **Then**：僅顯示 CARD_TYPE='H' 之估算分佈；處長可讀取（唯讀），行為與修正前一致

### TC-174-06：無新增路由

- **Given**：功能已上線
- **When**：檢查前端路由設定與 Sidebar 導覽
- **Then**：`/assignment/scoring` 路由與 Sidebar 項目均無變動，未新增任何新頁面
