# US-100：部長角色定義與 E07 全模組操作權限

> **Story ID**：US-100
> **Epic**：[E07 — 客戶名單分派](epic-brief.md)
> **模組**：M07 角色與可見範圍
> **優先級**：Must Have
> **階段**：Phase 1（MVP）
> **預估點數**：5

---

## User Story

**As a** Admin
**I want** 在 E07 系統中定義「部長（Director）」角色，確立其對 E07 全模組的完整操作權限
**So that** 部長可透過 CDMP 平台跨處瀏覽與操作所有 E07 配置面板（白名單維護、計分設定、部門比例、簽核、月跑觸發、名單 CRUD…），無需逐一向各處長索取資料

---

## 背景說明

本次重構引入「部長（Director）」作為 E07 內部的進階角色，代表管轄多位處長的上層主管。

**E07 角色權限矩陣（重要）**：

| 角色 | E07 全功能 | 個別業務比例設定 | 準備完成階段查詢 |
|------|-----------|----------------|----------------|
| 部長（Director） | 完整操作 | 完整操作 | 完整操作 |
| Admin | 完整操作（等同部長） | 完整操作 | 完整操作 |
| 處長（Section Chief） | **僅限**個別業務比例設定（可操作）+準備完成階段（可查詢） | 可操作 | 可查詢 |

> **[IMPORTANT]** 此角色矩陣為 E07 最終決策（2026-05-15 用戶確認）：除「個別業務比例設定」與「準備完成階段查詢」外，E07 其他所有功能（白名單維護、計分設定、部門比例設定、簽核、月跑觸發、名單 CRUD、M06 代碼維護…）一律**僅部長 + Admin 可操作**。

**角色指派入口**：E07 部長角色的指派由 **E02 帳號管理頁**執行（非 E07 內部設定頁），Admin 透過 E02 的角色指派功能（US-014）完成。

**補充規則**：
- **並任規則**：一個帳號可同時持有「部長」＋「處長」雙角色，以部長全範圍權限優先
- **Admin 繼承規則**：Admin 角色自動繼承 E07 全範圍存取，無需額外指派 E07 角色

> **[通知 spec-writer]** 本 Story 所定義的 E07 角色矩陣（部長/處長/Admin 對各模組的操作權限）必須同步更新至 **F002（auth/permission feature spec）**，請 spec-writer 在 F002 中新增「E07 角色矩陣」章節，作為全系統 E07 權限控制的權威定義來源。

## 驗收標準

### AC-1：Admin 於 E02 指派「部長」角色

- **Given** Admin 登入後進入 E02 帳號管理頁（US-014）
- **When** Admin 對某帳號指派「E07 部長（Director）」角色
- **Then** 該帳號取得 E07 全模組（M01 ~ M06）讀取與寫入權限
- **And** 部長的可見範圍涵蓋**所有**處長所管轄的名單、計分設定、分派比例、執行記錄、代碼維護
- **And** 此角色指派記錄寫入 `assignment_audit_log`
- **And** 指派操作的入口在 E02 帳號管理頁，E07 內部不另設角色指派 UI

### AC-2：部長對 E07 全模組擁有完整操作權限

- **Given** 帳號持有「部長」角色並登入 CDMP
- **When** 進入 E07 任意模組（M01 名單定義 / M02 計分設定 / M03 分派比例 / M04 分派執行 / M05 快照歷史 / M06 代碼維護）
- **Then** 顯示**所有**處長所設定的資料，不受處長轄區篩選限制
- **And** 所有操作按鈕（新增 / 編輯 / 停用 / 白名單維護 / 計分設定 / 部門比例設定 / 簽核 / 觸發月跑）均可使用
- **And** M06 白名單維護、M02 計分設定等原本僅部長 + Admin 可操作的功能，部長均有完整寫入權限

### AC-3：Admin 自動繼承 E07 全範圍存取

- **Given** 帳號持有系統「Admin」角色（E02 定義）
- **When** 進入 E07 任意模組
- **Then** 自動具備等同「部長」的全範圍存取，無需額外指派 E07 部長角色
- **And** 系統不需要（也不應要求）Admin 另行申請 E07 角色

### AC-4：並任部長＋處長的帳號使用行為

- **Given** 一個帳號同時持有「部長」＋「處長」雙角色
- **When** 該帳號進入 E07 任意模組
- **Then** 以「部長」的全範圍可見度與操作權限顯示（較高權限優先）
- **And** 不因並任處長而縮限可見範圍或操作能力

### AC-5：非 E07 角色帳號無法進入 E07 模組

- **Given** 帳號未持有 E07 任何角色（部長 / 處長）且非 Admin
- **When** 嘗試存取 E07 任意頁面或 API
- **Then** 系統回傳 403 Forbidden，前端導向「無存取權限」提示頁
- **And** 不顯示任何 E07 資料

### AC-6：處長無法操作部長專屬功能

- **Given** 帳號**僅**持有「處長」角色（非部長、非 Admin）
- **When** 嘗試進入或操作以下任一功能：M06 白名單維護 / M06 類別型欄位可選值管理 / M02 計分設定寫入 / M03 部門比例設定 / 月跑觸發 / 名單新增或停用
- **Then** 系統回傳 403 Forbidden（API 層）或前端不顯示對應操作按鈕
- **And** 處長進入這些功能頁面時，系統僅呈現唯讀視圖，無任何可操作的編輯控件

## 技術備註

- E07 角色（部長 / 處長）為 E07 應用層自訂角色，與 E02 系統層角色（Admin / User）分層管理，不互相污染
- 角色指派入口：**E02 帳號管理頁（US-014）**；E07 不另設指派 UI
- `SalesManagerGuard`（現有，F050+ 套用）負責處長層級存取控制；部長角色需新增對應 Guard 或擴充現有 Guard 邏輯，由 spec-writer 在 F002 中定義，并同步更新 Guard 實作
- Admin 繼承的實作方式：建議在 Guard 層檢查「是否為 Admin OR 持有 E07 部長角色」，避免硬編碼
- 「部長專屬功能」的 Guard 需區分：一般 E07 Guard（部長 + 處長均可進入，但處長僅唯讀）vs 部長專用 Guard（僅部長 + Admin 可寫入）
- 參照現有 E07 權限控制：`feedback_e07_controllers_use_sales_manager_guard.md`
- **[通知 spec-writer]**：F002 spec 需新增 E07 角色矩陣章節，詳列部長/處長/Admin 對 M01~M06 各功能的 CRUD 權限，作為全系統 Guard 實作依據

## 測試案例

### TC-100-01：部長帳號可看到所有處長設定

- **Given**：處長 A 管轄處設有 3 筆名單定義；處長 B 管轄處設有 2 筆名單定義；部長帳號持有 E07 Director 角色
- **When**：部長登入後進入名單定義清單頁（US-070）
- **Then**：清單顯示全部 5 筆名單定義（A 處 3 筆 + B 處 2 筆）

### TC-100-02：並任帳號以部長全範圍顯示

- **Given**：帳號同時持有「Director」＋「SalesManager」角色，所屬處僅管轄 2 筆名單
- **When**：帳號進入名單定義清單頁
- **Then**：顯示所有處全部名單（不限縮為 2 筆）

### TC-100-03：Admin 無需指派即有 E07 全存取

- **Given**：帳號僅持有 Admin 角色，未被指派任何 E07 角色
- **When**：進入 E07 任意模組
- **Then**：正常進入並顯示全範圍資料，不出現 403 或空資料

### TC-100-04：無角色帳號被拒於 E07 之外

- **Given**：帳號持有一般 User 角色（非 Admin、非 E07 角色）
- **When**：嘗試直接訪問 E07 頁面 URL
- **Then**：後端 API 回 403；前端顯示無存取權限提示，不洩漏任何 E07 資料

### TC-100-05：處長嘗試操作部長專屬功能被拒

- **Given**：帳號僅持有「處長」角色
- **When**：嘗試呼叫 M06 白名單新增 API（或觸發月跑 API、名單新增 API）
- **Then**：後端 API 回 403 Forbidden；前端對應操作按鈕不顯示或顯示為停用狀態

### TC-100-06：角色指派動作寫入稽核日誌

- **Given**：Admin 在 E02 帳號管理頁將帳號 X 指派為 E07 Director 角色
- **When**：儲存指派
- **Then**：`assignment_audit_log` 新增一筆，`action = 'ASSIGN_ROLE'`、`entity_type = 'e07_role'`、`after_payload` 包含帳號 ID 與角色名稱
