# US-114：個別業務比例設定階段推進至簽核

> **Story ID**：US-114
> **Epic**：[E07 — 客戶名單分派](epic-brief.md)
> **模組**：M03b 個別業務比例設定階段
> **優先級**：Must Have
> **階段**：Phase 1（MVP）
> **預估點數**：3

---

## User Story

**As a** 部長（Director）或 Admin（處長亦可，但需所有部門均完成設定）
**I want** 在確認所有部門的個別業務比例均完成設定後，將名單推進至「簽核」階段
**So that** 流程進入第四階段，等待部長正式核准，確保有明確的審核節點

---

## 背景說明

本 Story 是五階段流程（US-105）中，從「個別業務比例設定（Stage 3 / `personnel_ratio`）」推進至「簽核（Stage 4 / `approval`）」的操作節點。

**Actor 設計（OQ 確認）**：
- **部長 / Admin**：主要推進角色，可不受轄區限制推進任何名單
- **處長**：若本部門已完成設定，且系統驗證**所有部門均完成**，亦可觸發推進（無需部長代為操作；若有處長尚未設定，處長無法自行推進）
- **無代理處長情境**：若某部門無對應處長（處長帳號不存在或未指派），部長可代為設定並推進

推進前提：
1. 名單目前為個別業務比例設定階段（`stage = 'personnel_ratio'`）
2. **所有部門均已完成個別業務比例設定**（每個部門的業務員 RATION 加總 = 100%）
3. 操作者確認推進

---

## 驗收標準

### AC-1：推進按鈕顯示規則

- **Given** 名單 `stage = 'personnel_ratio'`
- **When** 部長 / Admin / 處長查看名單操作欄（US-105）
- **Then** 部長 / Admin 看到「推進至簽核」按鈕
- **And** 處長若本部門業務員比例已設定完成，亦看到「推進至簽核」按鈕；若本部門尚未完成，則按鈕為停用狀態並提示「本部門業務員比例尚未設定完成」

### AC-2：推進前置條件驗證（所有部門均完成）

- **Given** 任意角色點擊「推進至簽核」按鈕
- **When** 系統進行前置條件驗證
- **Then** 若仍有部門的業務員 RATION 加總 ≠ 100%（或尚未設定），系統顯示「以下部門的個別業務比例尚未完成設定：{DEPT_NAME_1}、{DEPT_NAME_2}…，請完成後再推進」，不執行推進
- **And** 前置條件通過後，彈出確認對話框

### AC-3：確認推進對話框

- **Given** 前置條件驗證通過
- **When** 系統彈出確認對話框
- **Then** 對話框顯示：「確認將名單『{LIST_NM}』（{LIST_NO}）推進至簽核階段？推進後個別業務比例將鎖定，無法再修改（如需修改請先 Rollback）。」
- **And** 對話框提供「確認推進」與「取消」兩個按鈕

### AC-4：執行推進

- **Given** 使用者在確認對話框點擊「確認推進」
- **When** 後端處理推進請求
- **Then** 系統將名單的 `stage` 從 'personnel_ratio' 更新為 'approval'
- **And** 個別業務比例欄位鎖定（stage != 'personnel_ratio' 時拒絕寫入）
- **And** 操作寫入 `assignment_audit_log`（action = 'ADVANCE_STAGE'，after_payload 含 stage = 'approval'）
- **And** 頁面成功提示「名單『{LIST_NM}』已推進至簽核階段，等待部長核准」，清單刷新

### AC-5：無代理處長時部長可代推進

- **Given** 某部門無對應處長帳號（或處長帳號尚未指派），部門業務員比例由部長代為設定
- **When** 部長確認所有部門均完成並推進
- **Then** 系統允許推進，不因「處長帳號缺失」而阻擋

### AC-6：月跑執行中禁止推進

- **Given** 目前有 AssignmentRun status = 'running' 的月跑
- **When** 任意角色嘗試點擊「推進至簽核」按鈕
- **Then** 推進按鈕為停用狀態，hover 顯示提示「分派執行中，無法推進」

---

## 技術備註

- `stage` 欄位更新：`ob_list_definition.stage = 'approval'`（從 'personnel_ratio'）
- 「所有部門均完成」驗證：查詢 `ob_empl_set` 中屬於本 LIST_NO 的各 DEPT_CODE 比例加總，確認每個部門均 = 100%
- 若某部門在 `ob_emphire` 有在職員工，但 `ob_empl_set` 中無對應設定記錄，視為「尚未完成」
- 處長推進權限邏輯：後端同時驗證「所有部門均完成」及「本帳號為處長」；若任一部門未完成，處長推進 API 回 422（「所有部門均需完成設定才可推進」）

## 測試案例

### TC-114-01：所有部門完成後正常推進（部長）

- **Given**：LIST_NO = 'OB202506001'，stage = 'personnel_ratio'；系統有 3 個部門，各部門業務員比例加總均 = 100%；部長帳號
- **When**：部長點擊「推進至簽核」→ 確認 → 點擊「確認推進」
- **Then**：`stage` 更新為 'approval'；稽核日誌新增 ADVANCE_STAGE；清單階段標籤更新

### TC-114-02：仍有部門未完成時推進被阻擋

- **Given**：LIST_NO = 'OB202506001'，stage = 'personnel_ratio'；部門 XTC0 業務員比例加總 = 80%（未完成）
- **When**：部長點擊「推進至簽核」
- **Then**：顯示「以下部門的個別業務比例尚未完成設定：XTC0…，請完成後再推進」；stage 不更新

### TC-114-03：處長推進（本部門完成，所有部門均完成）

- **Given**：LIST_NO = 'OB202506001'；所有 3 個部門均完成設定；處長 A（轄區 XTC0）帳號
- **When**：處長 A 點擊「推進至簽核」並確認
- **Then**：推進成功，`stage` 更新為 'approval'

### TC-114-04：處長推進但有其他部門未完成被阻擋

- **Given**：LIST_NO = 'OB202506001'；處長 A（XTC0）已完成，但部門 XTD0 尚未完成設定
- **When**：處長 A 點擊「推進至簽核」
- **Then**：回 422「所有部門均需完成設定才可推進；以下部門尚未完成：XTD0」

### TC-114-05：月跑中禁止推進

- **Given**：AssignmentRun status = 'running'
- **When**：部長嘗試推進
- **Then**：按鈕停用，顯示「分派執行中，無法推進」
