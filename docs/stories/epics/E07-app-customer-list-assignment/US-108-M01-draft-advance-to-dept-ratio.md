# US-108：草稿階段推進至部門比例設定

> **Story ID**：US-108
> **Epic**：[E07 — 客戶名單分派](epic-brief.md)
> **模組**：M01 名單定義
> **優先級**：Must Have
> **階段**：Phase 1（MVP）
> **預估點數**：3

---

## User Story

**As a** 部長（Director）或 Admin
**I want** 在確認草稿名單的篩選條件與 CR 回分設定無誤後，將名單推進至「部門比例設定」階段
**So that** 名單正式進入五階段流程，接下來可為各部門設定分派比例，流程推進有明確的確認節點

---

## 背景說明

本 Story 是五階段流程（US-105）中，從「草稿（Stage 1）」推進至「部門比例設定（Stage 2）」的操作節點。

推進前提：
1. 名單目前為草稿階段（`stage = 'draft'`）
2. 名單至少設定了一個篩選條件（US-106）
3. CR 回分開關已設定（US-107，預設啟用即算已設定）
4. 部長或 Admin 主動確認推進

推進後：
- 名單 `stage` 更新為 `'dept_ratio'`（部門比例設定階段）
- 篩選條件鎖定，不可再修改（進入唯讀）
- CR 回分開關鎖定，不可再修改
- 下一步操作由「部門比例設定」Epic（E 組，US-109~111）接手

---

## 驗收標準

### AC-1：草稿階段名單顯示「推進」按鈕

- **Given** 部長或 Admin 在 M01 名單定義清單（US-105）或名單詳情頁，看到某個 `stage = 'draft'` 的名單
- **When** 頁面顯示該名單的操作欄
- **Then** 顯示「推進至部門比例設定」按鈕（或等效文字）
- **And** 處長帳號進入相同頁面時，**不顯示「推進」按鈕**

### AC-2：推進前置條件驗證

- **Given** 部長或 Admin 點擊「推進至部門比例設定」按鈕
- **When** 系統進行前置條件驗證
- **Then** 若名單尚未設定任何篩選條件（US-106），系統顯示錯誤「請先設定至少一個篩選條件，再推進」，不執行推進
- **And** 前置條件通過後，彈出確認對話框

### AC-3：確認推進對話框

- **Given** 前置條件驗證通過
- **When** 系統彈出確認對話框
- **Then** 對話框顯示：「確認將名單『{LIST_NM}』（{LIST_NO}）推進至部門比例設定階段？推進後篩選條件將鎖定，無法再修改（如需修改請先退回草稿）。」
- **And** 對話框提供「確認推進」與「取消」兩個按鈕

### AC-4：執行推進

- **Given** 部長或 Admin 在確認對話框點擊「確認推進」
- **When** 後端處理推進請求
- **Then** 系統將名單的 `stage` 從 'draft' 更新為 'dept_ratio'
- **And** 篩選條件欄位鎖定（後端設定相應鎖定標記，或依 stage 判斷唯讀）
- **And** CR 回分開關欄位鎖定
- **And** 操作寫入 AssignmentAuditLog（action = 'ADVANCE_STAGE'、entity_type = 'list_definition'、after_payload 含 stage = 'dept_ratio'）
- **And** 頁面成功提示「名單『{LIST_NM}』已推進至部門比例設定階段」，清單刷新

### AC-5：推進後名單在清單頁顯示新階段

- **Given** 名單已推進至 'dept_ratio'
- **When** 部長在清單頁（US-105）查看
- **Then** 該名單的階段標籤更新為「部門比例設定」
- **And** 「推進至部門比例設定」按鈕消失，替換為（若有）部門比例設定的相關操作入口

### AC-6：推進後篩選條件不可修改

- **Given** 名單 `stage = 'dept_ratio'`
- **When** 部長或 Admin 進入名單詳情頁查看篩選條件
- **Then** 篩選條件顯示（唯讀），無任何「新增欄位」「修改值」「刪除條件」等操作控件
- **And** 若透過 API 嘗試修改篩選條件，後端回 422（「只有草稿階段才能修改篩選條件」）

### AC-7：月名單分派執行中禁止推進

- **Given** 目前有 AssignmentRun status = 'running' 的月名單分派
- **When** 部長或 Admin 嘗試點擊「推進」按鈕
- **Then** 推進按鈕為停用狀態，hover 顯示提示「分派執行中，無法推進名單定義」

---

## 技術備註

- `stage` 欄位更新：`ob_list_definition.stage = 'dept_ratio'`（從 'draft'）
- 「篩選條件鎖定」實作：後端依 stage 判斷，若 stage != 'draft' 則拒絕篩選條件寫入 API；前端依 stage 決定是否顯示編輯控件
- 月名單分派中資料鎖判斷：查詢 AssignmentRun 是否有 status = 'running' 記錄
- 推進後的下一步操作（部門比例設定）由 E 組 Story（US-109~111）定義，本 Story 不含部門比例設定邏輯

---

## 測試案例

### TC-108-01：草稿名單正常推進

- **Given**：LIST_NO = 'OB202506001'，stage = 'draft'，已設定 1 個篩選條件；部長帳號
- **When**：部長點擊「推進至部門比例設定」→ 確認對話框 → 點擊「確認推進」
- **Then**：`ob_list_definition.stage` 更新為 'dept_ratio'；稽核日誌新增 ADVANCE_STAGE 記錄；清單頁階段標籤更新

### TC-108-02：篩選條件為空時推進被阻擋

- **Given**：LIST_NO = 'OB202506002'，stage = 'draft'，**無任何篩選條件**
- **When**：部長點擊「推進至部門比例設定」
- **Then**：系統顯示「請先設定至少一個篩選條件，再推進」；stage 不更新

### TC-108-03：處長無法推進

- **Given**：帳號持有「處長」角色；LIST_NO = 'OB202506001'，stage = 'draft'
- **When**：處長嘗試呼叫推進 API
- **Then**：後端回 403 Forbidden；清單頁無「推進」按鈕

### TC-108-04：推進後篩選條件鎖定

- **Given**：LIST_NO = 'OB202506001'，stage = 'dept_ratio'
- **When**：部長嘗試呼叫修改篩選條件 API
- **Then**：後端回 422「只有草稿階段才能修改篩選條件」

### TC-108-05：月名單分派中禁止推進

- **Given**：AssignmentRun status = 'running'；LIST_NO = 'OB202506001'，stage = 'draft'
- **When**：部長嘗試點擊「推進」
- **Then**：推進按鈕停用，顯示「分派執行中，無法推進名單定義」提示

- **Blocked By**：US-106（草稿名單建立，才有 draft 狀態名單可推進）、US-107（CR 開關設定，推進前需已設定）、US-100（部長角色定義）
- **Blocks**：部門比例設定 Story（E 組，US-109~111；推進後才能設定部門比例）
