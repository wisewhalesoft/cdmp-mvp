# US-178：類別型篩選欄位可選值自動建議（從實際資料批次帶入）

> **Story ID**：US-178
> **Epic**：[E07 — 客戶名單分派](epic-brief.md)
> **模組**：M06 篩選欄位
> **優先級**：Should Have
> **階段**：Phase 2（Advanced）
> **預估點數**：8

---

## User Story

**As a** 部長（Director）或 Admin
**I want** 在新增或管理「類別型（categorical）」篩選欄位時，系統自動從該欄位的來源資料表查出實際存在的相異值（distinct values），並以核取清單方式讓我一次勾選、批次帶入為可選值
**So that** 我不需要針對每個類別型欄位（尤其是相異值數量多的欄位，如職業別 55 種、居住城市 22 種等）逐筆手動輸入可選值代碼與標籤，能更快、更準確地完成篩選欄位的可選值建置，降低因手動輸入造成的遺漏或打字錯誤

---

## 背景說明

現行 US-102（F075）新增篩選欄位時，只建立欄位本身的 metadata（`column_name` / `display_name` / `field_type` 等），不包含可選值。US-103（F076）維護類別型欄位的可選值，但目前僅支援「新增可選值」Modal 逐筆輸入 `option_value` / `option_label`。當一個類別型欄位的實際相異值數量較多（例如 US-172／F109 新增的客戶資料欄位中，職業別有 55 種、收入區間 9 種、居住城市 22 種），逐筆手動輸入既耗時，也容易輸入錯誤或遺漏部分真實存在的值。

本 Story 讓系統直接向欄位的來源資料表查詢該欄位「實際存在」的相異值，並以核取清單（全部預設勾選、可個別取消）的方式呈現給管理者確認，一次勾選批次帶入為可選值。此功能是 US-102 / US-103（F075 / F076）既有流程的**輔助強化**，不取代、也不變更既有的「逐筆手動新增可選值」操作路徑——兩者並存，管理者可自由選擇使用哪一種方式。

**兩個進入點**：

1. **新增篩選欄位 Modal（F075 / US-102，僅 `ob_pool_data`）**：目前新增篩選欄位 Modal 僅能新增來源為 `ob_pool_data` 的欄位（`customer_core` 之 8 個欄位為系統固定 seed，不透過此 Modal 新增）。當使用者在 Modal 中選定某欄位、且該欄位判定為類別型時，系統向 `ob_pool_data` 查詢該欄位之 distinct 值，以核取清單呈現，並提示「偵測到 N 個可選值，是否一併新增？」。使用者儲存時，欄位與勾選之可選值一併建立。
2. **可選值管理頁（F076 / US-103，適用 `ob_pool_data` 與 `customer_core` 兩種來源）**：對於已存在的類別型欄位（不論來源是 `ob_pool_data` 或 `customer_core`，含 US-172 新增之 8 個客戶資料欄位），提供「從實際資料帶入可選值」按鈕。系統依該欄位的資料來源（`data_source`）查詢對應來源表的 distinct 值，並將**已存在於該欄位可選值清單中的值排除**（去重），僅呈現尚未建立的候選值供勾選批次新增。

**欄位類別限定**：本功能僅適用於 `field_type = categorical` 的欄位；`numeric` / `date` 欄位不觸發任何 distinct 值查詢。

**可選值來源資料表規模**：`ob_pool_data` 為百萬列等級的案件資料表（`customer_core` 亦為數百萬列等級的客戶資料表），對其執行 distinct 值查詢須考慮效能、逾時與異常狀況（詳見驗收標準之邊界情境），不可讓使用者在查詢異常時看到「靜默空白」而誤判為欄位沒有可選值。

## 驗收標準

### AC-1：新增篩選欄位 Modal 選擇類別型欄位時觸發 Distinct 值偵測

- **Given** 部長或 Admin 在「新增篩選欄位」Modal 中，從欄位下拉選單選取某個尚未列入白名單的 `ob_pool_data` 欄位
- **When** 該欄位之欄位類別（`field_type`）確定為「類別型（categorical）」（無論是系統推斷之預選值或使用者手動選擇）
- **Then** 系統自動向 `ob_pool_data` 查詢該欄位的實際 distinct 值
- **And** 查詢完成後，以核取清單（checklist）呈現偵測到的值，並顯示提示文字「偵測到 N 個可選值，是否一併新增？」
- **And** 清單中所有值預設為勾選（全選）狀態

### AC-2：新增篩選欄位 Modal 選擇數值型或日期型欄位時不觸發偵測

- **Given** 部長或 Admin 在「新增篩選欄位」Modal 中，欄位類別確定為「數值型（numeric）」或「日期型（date）」
- **When** 欄位類別非類別型
- **Then** 系統不執行 distinct 值查詢，不顯示可選值核取清單
- **And** 若使用者先前已因選擇類別型而顯示核取清單，之後又將欄位類別改為 numeric/date，核取清單應隱藏或清除，不影響後續儲存流程

### AC-3：新增篩選欄位時可個別取消勾選偵測到的候選值

- **Given** 核取清單已顯示 N 個偵測到的候選值，全部預設勾選
- **When** 使用者取消勾選其中部分值
- **Then** 僅保留使用者仍勾選的值，作為儲存時要建立的可選值
- **And** 取消勾選不影響欄位本身的建立流程

### AC-4：新增篩選欄位時全部取消勾選候選值 → 僅建立欄位，不建立任何可選值

- **Given** 核取清單中使用者將全部候選值取消勾選
- **When** 使用者點擊「儲存」
- **Then** 系統僅建立該篩選欄位本身（`field_type = categorical`、`is_active = true`），不建立任何可選值
- **And** 此結果與「不使用本功能、直接透過既有新增欄位流程建立欄位」之結果一致（欄位建立後，管理者仍可再透過 F076 既有流程逐筆新增可選值）

### AC-5：儲存後欄位與勾選之可選值一併建立（進入點 1 主流程）

- **Given** 使用者已將欄位類別設為 categorical，核取清單中勾選了 M 個候選值（M ≥ 1）
- **When** 使用者點擊「儲存」
- **Then** 系統建立該篩選欄位，並同時將勾選的 M 個候選值以可選值（options）形式一併建立，狀態為啟用
- **And** 建立完成後，管理者可在 F076 可選值管理頁直接看到這 M 個可選值，無需再手動逐筆新增
- **And** 若欄位建立與可選值批次建立中有任一部分失敗，系統須明確告知使用者哪一部分成功、哪一部分失敗，避免使用者誤以為「欄位與可選值皆已建立完成」（精確的交易邊界設計見待解決問題 OQ-178-03）

### AC-6：可選值管理頁對既有類別型欄位提供「從實際資料帶入可選值」功能

- **Given** 部長或 Admin 在可選值管理頁（F076 / US-103）檢視某個已存在的類別型欄位
- **When** 使用者點擊該欄位對應的「從實際資料帶入可選值」按鈕
- **Then** 系統依該欄位的資料來源（`data_source = ob_pool_data` 或 `customer_core`）向對應的來源資料表查詢實際 distinct 值
- **And** 此功能同時支援 `ob_pool_data` 來源欄位與 `customer_core` 來源欄位（含 US-172 新增之 8 個客戶資料欄位，例如職業別、居住城市）

### AC-7：可選值管理頁的候選清單排除已存在的可選值（去重）

- **Given** 某類別型欄位目前已有 K 個可選值（不論啟用或停用狀態）
- **When** 使用者點擊「從實際資料帶入可選值」，系統查得該欄位來源資料表共有 N 個 distinct 值
- **Then** 核取清單僅呈現「N 個 distinct 值中，尚未存在於該欄位可選值清單」的候選值（已存在的 K 個一律排除，含已停用者亦視為已存在而排除）
- **And** 候選清單同樣預設全選，使用者可個別取消勾選

### AC-8：可選值管理頁批次新增勾選之候選值，清單即時刷新

- **Given** 使用者在候選清單中勾選了部分或全部候選值
- **When** 使用者確認批次新增
- **Then** 系統將勾選的候選值以 `optionValue = distinct 值`、狀態啟用 的方式批次新增至該欄位的可選值清單
- **And** 新增完成後，可選值列表立即刷新，顯示新加入的可選值
- **And** 未被勾選的候選值不受影響，不會被新增

### AC-9：候選值清單為空時顯示友善提示（無新可選值可帶入）

- **Given** 使用者點擊「從實際資料帶入可選值」，系統查得來源資料表的全部 distinct 值皆已存在於該欄位的可選值清單中（不論啟用或停用）
- **When** 系統完成比對
- **Then** 顯示「無新可選值可帶入」之友善提示，不顯示空的核取清單，亦不阻擋使用者關閉此流程

### AC-10：批次帶入之可選值預設標籤，維持既有編輯機制

- **Given** 系統批次建立可選值（無論來自進入點 1 或進入點 2）
- **When** 可選值建立完成
- **Then** `optionValue` 直接採用該 distinct 值本身；`optionLabel` 預設同樣採用該值本身（`optionValue = optionLabel`）
- **And** 業務主管可事後透過既有的可選值編輯機制修改 `optionLabel`（例如將代碼值改標示為更易懂的中文名稱，如 `prod_kind` 代碼），此編輯行為沿用既有 F076 機制，不在本 Story 新增或變更
- **And** 對於本身已是中文顯示值的欄位（如 US-172 之 `customer_core` `_desc` 欄位），`optionValue = optionLabel` 直接呈現中文，通常不需再編輯

### AC-11：Distinct 值筆數超過上限時顯示警告，不全數列出

- **Given** 某欄位來源資料表的 distinct 值數量超過系統設定的上限（建議預設值約 200 筆；精確門檻與是否可調整見待解決問題 OQ-178-01）
- **When** 系統執行 distinct 值查詢
- **Then** 系統不將全部筆數塞入核取清單，改為顯示警告訊息，告知使用者「偵測到的相異值數量過多，此欄位可能不適合以類別型管理，或請確認欄位選型是否正確」
- **And** 使用者仍可選擇（a）取消本次偵測、僅建立/保留欄位不帶入任何可選值，或（b）改為透過既有逐筆新增可選值之流程手動處理

### AC-12：來源資料表尚未就緒時顯示明確錯誤，不可靜默留空

- **Given** 欄位之來源資料表（`ob_pool_data` 或 `customer_core`）尚未完成 ETL 載入或暫時無法查詢
- **When** 使用者觸發 distinct 值偵測（進入點 1 或進入點 2）
- **Then** 系統必須顯示明確的錯誤訊息，告知使用者來源資料尚未就緒，建議稍後再試或聯繫系統管理員
- **And** 系統**不得**以「無任何提示的空白核取清單」呈現此狀況（本專案已有因逾時/資料未就緒被前端靜默吞掉、呈現空白造成業務誤判的教訓，本功能須明確避免重蹈覆轍）

### AC-13：Distinct 值查詢逾時時顯示明確錯誤，不可靜默留空

- **Given** distinct 值查詢因來源資料表規模過大或系統忙碌而執行時間過長
- **When** 查詢超過系統可接受的等待時間
- **Then** 系統必須顯示明確的逾時錯誤訊息（而非長時間無回應或靜默顯示空清單），並提供使用者重試的操作
- **And** 逾時不影響欄位本身既有的建立/編輯功能，使用者仍可選擇不使用本功能、改為手動新增可選值

### AC-14：欄位全部為 NULL 或無有效值時顯示空狀態

- **Given** 某欄位在來源資料表中所有列的值皆為 NULL，或該欄位目前無任何非 NULL 值
- **When** 使用者觸發 distinct 值偵測
- **Then** 系統明確顯示「未偵測到任何可選值」之空狀態提示（與 AC-12／AC-13 的錯誤狀態明確區隔，不可混淆為查詢失敗）
- **And** 使用者仍可正常完成欄位建立（進入點 1）或關閉此流程（進入點 2）

### AC-15：重複值批次新增為冪等操作，不報錯

- **Given** 使用者於進入點 2 勾選之候選值中，某個值在確認送出前後已被其他管理者以其他方式新增為可選值（例如另一位管理者同時逐筆手動新增）
- **When** 系統執行批次新增
- **Then** 對已存在的值略過處理，不視為錯誤（不中斷其餘候選值的新增），並於結果中告知使用者實際新增筆數與略過筆數
- **And** 使用者不會因此收到「新增失敗」的錯誤訊息

### AC-16：部長 / Admin 可使用本功能之兩個進入點

- **Given** 使用者具備部長或 Admin 身份
- **When** 使用者進入「新增篩選欄位」Modal，或進入既有類別型欄位的可選值管理頁
- **Then** 使用者可看到並操作「偵測 distinct 值」相關核取清單，以及「從實際資料帶入可選值」之批次新增按鈕

### AC-17：處長無法看到或操作本功能之寫入介面

- **Given** 使用者具備「處長」角色（非部長、非 Admin）
- **When** 使用者進入既有類別型欄位的可選值管理頁（唯讀模式；處長本就無法開啟「新增篩選欄位」流程，故進入點 1 情境對處長不適用）
- **Then** 頁面**不顯示**「從實際資料帶入可選值」按鈕與批次新增相關操作
- **And** 若處長嘗試直接呼叫本功能對應的查詢或批次寫入介面，後端回應 403 Forbidden（沿用 F075 / F076 既有處長唯讀規則）

### AC-18：一般業務人員（無部長/處長/Admin 角色）無法存取本功能

- **Given** 使用者不具備部長、處長、Admin 任一角色
- **When** 使用者嘗試進入 M06「篩選欄位」相關頁面
- **Then** 使用者無法進入頁面（沿用 F075 / F076 既有頁面存取權限），因此亦無法接觸本功能之任何操作入口

## 本 Story 不含的範圍（留給 spec / architect / TDD）

- Distinct 值查詢的後端實作方式（SQL 設計、索引策略、cap 機制的確切門檻值、逾時秒數等）由 spec-writer / system-architect 決定
- 批次新增可選值之交易邊界設計（欄位建立與可選值批次建立如何原子化或分步驟處理、失敗時的復原策略）由 system-architect 決定
- 核取清單 UI 元件的視覺設計、互動細節（例如是否需要搜尋框、分頁、全選/全不選捷徑按鈕）由 ui-ux-designer 決定
- 批次新增操作的稽核日誌（`assignment_audit_log`）確切資料結構（逐筆記錄 vs 彙總一筆）由 spec-writer 決定
- `optionLabel` 二次翻譯來源（例如透過既有代碼對照表提供比 distinct 值本身更易懂的顯示文字）不在本 Story 範圍；本 Story 維持「`optionLabel` 預設 = distinct 值本身，事後可手動編輯」之既有機制
- 既有「新增可選值」Modal 逐筆手動輸入流程（F076 AC-4）不受本 Story 影響，維持原樣、與本功能並存
- 新增篩選欄位 Modal 目前僅支援 `ob_pool_data` 欄位之既有限制不在本 Story 變更範圍；若未來開放透過 Modal 新增 `customer_core` 欄位，是否同步支援本功能列為後續 backlog（見 OQ-178-05）

## 測試案例

### TC-178-01：新增篩選欄位選擇類別型欄位 → 顯示偵測到的候選值核取清單（全選）

- **Given**：部長開啟「新增篩選欄位」Modal，選取一個尚未列入白名單的 `ob_pool_data` 類別型欄位
- **When**：欄位類別確定為 categorical
- **Then**：系統顯示核取清單，列出偵測到的 distinct 值，全部預設勾選，並顯示「偵測到 N 個可選值，是否一併新增？」

### TC-178-02：新增篩選欄位選擇數值型欄位 → 不觸發偵測，無核取清單

- **Given**：部長在 Modal 中選取欄位類別為 numeric 的欄位
- **When**：欄位類別確定
- **Then**：不顯示任何 distinct 值核取清單，Modal 正常進行至欄位基本資訊填寫

### TC-178-03：新增篩選欄位取消勾選部分候選值後儲存 → 僅建立勾選的可選值

- **Given**：核取清單顯示 5 個候選值，部長取消勾選其中 2 個
- **When**：部長點擊「儲存」
- **Then**：欄位建立成功，且僅有 3 個仍勾選的值被建立為可選值

### TC-178-04：新增篩選欄位全部取消勾選後儲存 → 僅建立欄位，無可選值

- **Given**：核取清單中部長將全部候選值取消勾選
- **When**：部長點擊「儲存」
- **Then**：欄位建立成功，可選值管理頁該欄位下無任何可選值

### TC-178-05：可選值管理頁點擊「從實際資料帶入可選值」→ 候選清單排除已存在的值

- **Given**：某類別型欄位已有 3 個可選值；來源資料表實際有 8 個 distinct 值
- **When**：部長點擊「從實際資料帶入可選值」
- **Then**：候選清單僅顯示 5 個尚未存在的值（8 減去已存在的 3 個）

### TC-178-06：可選值管理頁批次新增勾選候選值 → 清單即時刷新

- **Given**：候選清單顯示 5 個候選值，部長勾選其中 4 個並確認新增
- **When**：批次新增完成
- **Then**：可選值列表立即刷新，新增的 4 個可選值出現於列表，狀態為啟用

### TC-178-07：customer_core 來源欄位（如職業別）使用本功能 → 正確從 customer_core 查詢 distinct 值

- **Given**：白名單中「職業別」欄位（`data_source = customer_core`）已存在，尚未維護任何可選值
- **When**：部長於可選值管理頁點擊該欄位之「從實際資料帶入可選值」
- **Then**：系統從 `customer_core` 表（而非 `ob_pool_data`）查得 55 種職業別 distinct 值，供勾選批次新增

### TC-178-08：全部 distinct 值皆已存在 → 顯示「無新可選值可帶入」

- **Given**：某欄位的可選值清單已涵蓋來源資料表全部 distinct 值
- **When**：部長點擊「從實際資料帶入可選值」
- **Then**：顯示「無新可選值可帶入」提示，不顯示空核取清單

### TC-178-09：distinct 值筆數超過上限 → 顯示警告，不列出全部候選值

- **Given**：某欄位來源資料表之 distinct 值數量超過系統設定上限
- **When**：使用者觸發 distinct 值偵測
- **Then**：系統顯示「相異值數量過多」警告，不將全部筆數塞入核取清單

### TC-178-10：來源資料表尚未就緒 → 顯示明確錯誤訊息，非空白清單

- **Given**：`ob_pool_data`（或 `customer_core`）ETL 尚未完成載入
- **When**：使用者觸發 distinct 值偵測
- **Then**：系統顯示明確錯誤訊息，告知資料尚未就緒；不顯示無提示的空白清單

### TC-178-11：查詢逾時 → 顯示明確逾時錯誤訊息與重試選項

- **Given**：distinct 值查詢因故執行超過可接受等待時間
- **When**：逾時發生
- **Then**：系統顯示明確逾時錯誤訊息，並提供重試操作；不留下靜默空白畫面

### TC-178-12：欄位全部為 NULL → 顯示「未偵測到任何可選值」空狀態

- **Given**：某欄位在來源資料表中全部列皆為 NULL
- **When**：使用者觸發 distinct 值偵測
- **Then**：系統顯示「未偵測到任何可選值」之空狀態提示，與錯誤狀態明確區隔

### TC-178-13：批次新增遇重複值 → 略過不報錯，回報實際新增/略過筆數

- **Given**：使用者勾選的候選值中，有 1 個在送出當下已被其他方式新增為可選值
- **When**：系統執行批次新增
- **Then**：該值被略過，其餘候選值正常新增成功，系統不回傳整體失敗，並回報實際新增與略過的筆數

### TC-178-14：處長進入可選值管理頁 → 無「從實際資料帶入可選值」按鈕；直接呼叫介面回 403

- **Given**：帳號僅持有「處長」角色
- **When**：進入某類別型欄位的可選值管理頁，或嘗試直接呼叫本功能對應的查詢/批次寫入介面
- **Then**：頁面不顯示「從實際資料帶入可選值」按鈕；直接呼叫介面後端回 403 Forbidden
