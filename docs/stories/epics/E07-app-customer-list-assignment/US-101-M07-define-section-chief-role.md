# US-101：處長角色定義與可見範圍

> **Story ID**：US-101
> **Epic**：[E07 — 客戶名單分派](epic-brief.md)
> **模組**：M07 角色與可見範圍
> **優先級**：Must Have
> **階段**：Phase 1（MVP）
> **預估點數**：5

---

## User Story

**As a** Admin
**I want** 在 E07 系統中定義「處長（Section Chief）」角色，確立其**嚴格限縮**的操作範圍
**So that** 處長僅能操作「個別業務比例設定」並查詢「準備完成階段」，無法誤觸其他 E07 功能，系統資料安全可控

---

## 背景說明

「處長（Section Chief）」對應現有「業務主管（SalesManager）」角色的組織名稱。本次重構後，處長的可操作範圍**大幅收斂**，與原設計有重大差異：

**處長可操作範圍（最終決策，2026-05-15 確認）**：

| 功能 | 處長可否操作 | 備註 |
|------|------------|------|
| 個別業務比例設定 | **可操作** | 處長唯一可寫入的功能 |
| 準備完成階段查詢 | **可查詢（唯讀）** | 查看分派結果，無法修改 |
| M01 名單定義（新增/編輯/停用） | 無權 | 僅部長 + Admin |
| M02 計分設定（寫入） | 無權 | M02 為全系統共用，僅部長 + Admin 可維護 |
| M02 計分設定（查看） | **完全不可見** | **Nav 完全不顯示 M02 入口**（OQ-C-03 確認，2026-05-15）|
| M03 部門比例設定 | 無權 | 僅部長 + Admin |
| M06 白名單維護 | 無權 | 僅部長 + Admin |
| M06 類別型欄位可選值 | 無權 | 僅部長 + Admin |
| 月跑觸發 | 無權 | 僅部長 + Admin |
| 簽核操作 | 無權 | 僅部長 + Admin |

> **[重要]** 此權限矩陣的權威定義在 **F002（auth/permission feature spec）**。spec-writer 須同步更新 F002，加入 E07 角色矩陣章節。

**「轄區」識別方式**：以 `created_by` 欄位過濾（名單/業務員的建立者帳號 ID），系統**不**引入獨立的 `section_id` 欄位。

**角色指派入口**：處長角色的指派由 **E02 帳號管理頁**執行（非 E07 內部設定頁），Admin 透過 E02 的角色指派功能（US-014）完成。

## 驗收標準

### AC-1：Admin 於 E02 指派「處長」角色

- **Given** Admin 登入後進入 E02 帳號管理頁（US-014）
- **When** Admin 對某帳號指派「E07 處長（SectionChief）」角色
- **Then** 該帳號取得「個別業務比例設定」的寫入權限，以及「準備完成階段查詢」的唯讀權限
- **And** 指派操作的入口在 E02 帳號管理頁，E07 內部不另設角色指派 UI
- **And** 此操作寫入 `assignment_audit_log`

### AC-2：處長「個別業務比例設定」操作範圍限轄區

- **Given** 帳號持有「處長」角色並登入 CDMP
- **When** 進入「個別業務比例設定」頁面
- **Then** 僅顯示本處長所轄業務員的比例設定（以 `created_by` 過濾，即名單或業務員紀錄的建立者等於本帳號 ID）
- **And** 其他處長轄區的業務員資料**不顯示**，也**不可存取**

### AC-3：處長嘗試存取他人轄區資料被拒

- **Given** 帳號持有「處長」角色
- **When** 嘗試透過 API 修改他人轄區的個別業務比例資料（即便知道 ID）
- **Then** 後端回傳 403 Forbidden，不執行任何寫入操作
- **And** 前端不顯示他人轄區的編輯按鈕或連結

### AC-4：處長對 M02 計分設定完全不可見（OQ-C-03 決議）

- **Given** 帳號持有「處長」角色並登入 CDMP
- **When** 頁面載入系統側邊導覽列（Nav）
- **Then** **M02 計分設定入口完全不顯示**（Nav 隱藏），處長無法感知 M02 存在
- **And** 若處長透過直接輸入 URL 嘗試進入 M02 任意頁面，後端回傳 403 Forbidden（防禦性守衛）
- **And** 前端路由守衛同樣阻擋並導向「無存取權限」頁面
- **And** 若處長嘗試直接呼叫 M02 任意寫入或讀取 API，後端回傳 403 Forbidden

> **注意（OQ-C-03 確認）**：M02 對處長改為「Nav 完全不可見」，不提供唯讀進入。即使知道 URL 也無法操作（後端守衛防禦）。

### AC-5：處長無法進行部長專屬功能的任何操作

- **Given** 帳號持有「處長」角色（非部長、非 Admin）
- **When** 嘗試存取以下任一功能：M01 名單新增 / M01 名單編輯 / M01 名單停用 / **M02 計分設定（含查看與寫入，Nav 完全隱藏）** / M03 部門比例設定 / M06 白名單維護（新增/編輯/停用） / M06 類別型欄位可選值管理 / 月跑觸發 / 簽核操作
- **Then** 後端 API 回傳 403 Forbidden，前端 Nav 不顯示 M02 入口，其他操作不顯示對應操作按鈕（或按鈕顯示為停用狀態並附提示）
- **And** 不洩漏任何被限制的操作入口

### AC-6：處長查看「準備完成階段」（唯讀）

- **Given** 帳號持有「處長」角色
- **When** 進入「準備完成階段」查詢頁面
- **Then** 可查看本處長轄區的準備完成階段資料（依 `created_by` 過濾）
- **And** 頁面為唯讀，不顯示任何可修改的控件
- **And** 無法查看其他處長轄區的準備完成階段資料

### AC-7：撤銷處長角色後立即失效

- **Given** Admin 撤銷帳號的「處長」角色
- **When** 該帳號下一次發出 E07 API 請求（或刷新頁面）
- **Then** 後端返回 403；前端導向無存取權限頁
- **And** 此操作寫入 `assignment_audit_log`

## 技術備註

- **「轄區」識別**：以 `created_by` 欄位過濾（名單/業務員紀錄的建立者帳號 ID），**不**引入獨立 `section_id` 欄位。spec-writer 在 F002 中確認此查詢過濾邏輯
- 現有 `SalesManagerGuard` 對應「處長」層級存取控制（`@RequireSalesManager()`），本 Story 為其正式語意文件化；Guard 行為需調整以符合本次收斂的操作範圍
- **M02 計分設定**：為全系統共用一份設定（非各處長各自維護），由部長 + Admin 統一維護；處長對 M02 僅有唯讀權限，不存在多人同時寫入的衝突問題
- Guard 設計建議（由 system-architect / spec-writer 決策）：
  - `SalesManagerGuard`（現有）：允許處長 + 部長 + Admin 進入，但業務層需區分可寫入與唯讀
  - `DirectorGuard`（新增）：僅部長 + Admin 可通過，用於白名單維護 / M02 寫入 / 月跑觸發 / 名單 CRUD 等功能
- **[通知 spec-writer]**：F002 spec 需新增 E07 角色矩陣章節，並定義兩層 Guard 的實作規格（`SalesManagerGuard` vs `DirectorGuard`），以及 `created_by` 過濾邏輯的標準實作模式

## 測試案例

### TC-101-01：處長帳號只能看到個別業務比例設定（限轄區）

- **Given**：處長 A 帳號（ID: user-A），其建立的業務員比例設定有 3 筆（created_by = user-A）；系統另有其他處長的 5 筆設定（created_by ≠ user-A）
- **When**：處長 A 進入個別業務比例設定頁面
- **Then**：僅顯示 3 筆（created_by = user-A），不顯示其他處的 5 筆

### TC-101-02：處長嘗試寫入他人轄區資料被拒

- **Given**：處長 A 知道他人個別業務比例設定的資料 ID（屬處長 B 轄區，created_by ≠ user-A）
- **When**：處長 A 直接呼叫編輯 API 傳入該 ID
- **Then**：後端回 403 Forbidden，不執行任何更新操作

### TC-101-03：處長的 Nav 中 M02 計分設定入口完全不顯示（OQ-C-03）

- **Given**：帳號僅持有「處長」角色
- **When**：登入後查看系統側邊 Nav
- **Then**：**M02 計分設定連結完全不出現**於 Nav 中，處長無法從 UI 感知 M02 存在

### TC-101-04：處長透過直接 URL 嘗試存取 M02 被拒（OQ-C-03 防禦性守衛）

- **Given**：帳號僅持有「處長」角色
- **When**：直接在瀏覽器輸入 M02 計分設定任意頁面 URL，或直接呼叫 M02 讀取 / 寫入 API
- **Then**：前端路由守衛導向「無存取權限」頁面；後端回 403 Forbidden，不回傳任何計分設定資料

### TC-101-05：處長嘗試新增名單定義被拒

- **Given**：帳號僅持有「處長」角色
- **When**：嘗試呼叫 M01 名單新增 API，或前端點擊名單定義頁面
- **Then**：前端不顯示「新增名單」按鈕（或按鈕停用）；後端若收到 POST 請求回 403

### TC-101-06：處長嘗試觸發月跑被拒

- **Given**：帳號僅持有「處長」角色
- **When**：嘗試呼叫月跑觸發 API
- **Then**：後端回 403 Forbidden；前端不顯示觸發按鈕

### TC-101-07：撤銷處長角色後立即無法存取

- **Given**：帳號持有處長角色並已登入
- **When**：Admin 撤銷其處長角色；帳號再次請求 E07 API
- **Then**：API 回 403；前端顯示無存取權限

### TC-101-08：並任部長+處長帳號以部長權限優先

- **Given**：帳號同時持有「Director」+「SectionChief」
- **When**：嘗試操作名單新增、月跑觸發等部長專屬功能
- **Then**：操作成功執行（以部長全權限處理）
