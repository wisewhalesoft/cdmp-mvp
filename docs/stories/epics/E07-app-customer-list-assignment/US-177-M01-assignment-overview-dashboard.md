## User Story

**As a** 部長（Director）、處長（Section Chief）或 Admin
**I want** 進入「客戶名單分派」時，第一眼就看到一個以本月營運狀況為中心的總覽儀表板——名單流程還卡在哪、能不能觸發月名單分派、這個月大概要打多少通電話、上次月跑結果準不準
**So that** 不需要逐一點開名單定義、月名單分派觸發、試算頁、執行歷史等多個頁面拼湊資訊，就能快速判斷本月分派作業的整體健康狀況，並直接點擊鑽入需要處理的項目

---

## 背景說明

**現況問題**：目前使用者從側邊欄點入「客戶名單分派」模組，第一個看到的頁面是「篩選欄位」（M06，代碼維護性質的頁面）。這對部長 / 處長而言毫無業務意義——篩選欄位是低頻的設定維護功能，不是每月都要看的東西。使用者真正每次登入都想知道的是「這個月的名單分派進度到哪了」，但現行系統沒有任何頁面一次回答這個問題，必須自行拼湊 M01 Kanban、M04 觸發頁、Stage 0 試算頁、M05 執行歷史四個地方的資訊。

**本 Story 新增「分派總覽」（Assignment Overview）頁面**，作為「客戶名單分派」模組新的入口首頁（sidebar 第 1 項），取代「篩選欄位」原本的首頁位置（篩選欄位降為 sidebar 第 2 項，功能本身不變、路由不變）。路由為 `/assignment/overview`。

**本頁面为純唯讀彙總視圖**，不新增任何業務邏輯或寫入操作；四大區塊全部彙總既有頁面已在提供的資料，讓使用者從「總覽」直接點擊鑽入對應的既有功能頁完成實際操作：

1. **名單階段待辦**：本月各名單卡在五階段流程（草稿 / 部門比例 / 個別比例 / 待簽核 / 準備完成）的哪個位置，以及有哪些名單尚未就緒
2. **月名單分派就緒狀態**：目前能不能觸發月名單分派（是否所有名單都 ready、ETL 來源資料與計分卡是否就緒）、目前月名單分派的執行狀態
3. **預計撥打量**：本月與下月的預估電訪工作量，含每日分佈、部門分佈、人均每日可行性
4. **最近一次月跑結果**：選定月份最近一次完成的月名單分派，其部門實際落差與 CARD_LEVEL / TIER 分布概況

> **角色術語提醒（本 Epic 既有定義，非本 Story 新規）**：
> - **部長（businessRole = `director`）**：分派作業的實際操作者，**不限轄區**，可查看全公司所有部門資料，並擁有觸發月名單分派等寫入權限（觸發本身仍在既有「觸發月名單分派」頁完成，本頁僅顯示狀態）。
> - **處長（businessRole = `section_chief`）**：**唯讀**審閱角色，且**自動限定於本人轄區部門**（service 層 scope filter，屬安全邊界，非僅前端遮罩）。
> - **admin**：系統管理者，視角等同部長（全公司、不限轄區），唯讀。
> - **user**：一般使用者，無 E07 存取權限。

## 驗收標準

### AC-1：頁面存取範圍與角色守衛

- **Given** 任意已登入使用者導航至 `/assignment/overview`
- **When** 頁面進行存取權限判斷
- **Then** `businessRole = 'director'`、`businessRole = 'section_chief'`、`role = 'admin'` 三者均可成功進入頁面（對齊既有 `DirectorOrSectionChief` 守衛，與 US-168 對 Stage 0 試算頁的存取矩陣一致）
- **And** `role = 'user'`（一般使用者）進入時，主體內容被封鎖，顯示「分派總覽為部長 / 處長 / Admin 專屬功能」說明卡，不顯示任何區塊資料
- **And** `admin` 的資料範圍視角等同部長（全公司、不限轄區）

### AC-2：處長轄區範圍標示與資料限定

- **Given** 使用者為處長（`section_chief`）
- **When** 頁面載入
- **Then** 頁面頂端顯示「轄區檢視」識別徽章，並標示處長所屬部門名稱（與 US-105 AC-4、US-168 AC-1 既有徽章語意一致）
- **And** 四大區塊中所有「依部門拆分」的數據（名單階段待辦、預計撥打量之部門分佈、最近月跑結果之部門落差）僅顯示處長本人轄區部門的資料列，其他部門資料列**不顯示**（非僅遮罩數字）
- **And** 依既有部門 scope 端點行為（如 `dept-estimate` 的 `scope.scoped = true`），組織級加總 / 缺口類數據（如全公司總撥打量、全公司分派缺口）在處長視角下**不顯示**（因該類數值在 scoped 模式下本就無意義或後端本就不回傳）

### AC-3：分派作業月份選擇器（四區塊共用）

- **Given** 使用者進入分派總覽頁
- **When** 頁面載入
- **Then** 頁面頂端顯示「分派作業月份」選擇器，預設值為下月（`target_work_ym`，與觸發月名單分派頁 US-138 之預設邏輯一致）
- **And** 選擇器變更月份後，四大區塊（名單階段待辦 / 就緒狀態 / 預計撥打量 / 最近一次月跑結果）**全部**依新選定月份重新載入資料
- **And** 月份切換期間，尚未回應的區塊各自顯示載入中狀態（見 AC-15），不阻擋其他已完成區塊的顯示

### AC-4：區塊一 — 名單階段待辦 KPI 卡

- **Given** 分派總覽頁已載入選定月份資料
- **When** 頁面呈現「名單階段待辦」區塊
- **Then** 顯示五張 KPI 卡，分別對應五個流程階段（沿用既有 Kanban 五階段命名：草稿 / 部門比例 / 個別比例 / 待簽核 / 準備完成），各卡顯示該階段的名單數量
- **And** 點擊任一階段 KPI 卡，導向 M01 名單定義主頁（US-130 Kanban），並以該階段為篩選條件（或捲動聚焦至該欄）
- **And** 若選定月份查無任何名單，五張卡均顯示 0，並顯示引導文案「本月尚無名單定義，請至名單定義頁建立」，附「前往建立」連結

### AC-5：區塊一 — 未完成名單待辦清單

- **Given** 選定月份存在尚未達「準備完成」階段的名單
- **When** 「名單階段待辦」區塊呈現
- **Then** 顯示「未完成名單待辦清單」，逐筆列出每份未就緒名單的 LIST_NO、LIST_NM（名稱）、目前卡在的階段名稱
- **And** 每一筆均可點擊，點擊後導向該名單於 M01 的詳情（Detail Drawer，對齊 US-131），供使用者直接處理
- **And** 若本月所有名單皆已「準備完成」（或本月無 active 名單），此清單顯示「目前無未完成名單」的正向提示，而非空白

### AC-6：區塊二 — 月名單分派就緒狀態摘要

- **Given** 分派總覽頁已載入選定月份資料
- **When** 頁面呈現「月名單分派就緒狀態」區塊
- **Then** 顯示是否所有 active 名單皆已就緒（就緒 / 未就緒燈號）、已就緒名單數 / 總 active 名單數（如「8 / 10」）
- **And** 顯示目前月名單分派狀態（無執行紀錄 / 等待中 / 執行中 / 已完成 / 失敗），狀態需清楚區分於名單就緒狀態（兩者為不同維度，不可混為一談）
- **And** 若目前有執行中（`running`）的月名單分派，額外標示「月名單分派執行中」提示

### AC-7：區塊二 — ETL 來源資料前置檢查與計分卡狀態

- **Given** 「月名單分派就緒狀態」區塊已載入
- **When** 頁面呈現前置檢查明細
- **Then** 顯示 4 項來源資料的同步狀態，各自標示通過 / 未通過（沿用既有前置檢查頁面之業務命名：客戶名單池、在職名單、工作日曆、最低回收上限）
- **And** 顯示計分卡（計分版本）是否為啟用狀態（是 / 否）
- **And** 任一項目未通過時，以警示樣式呈現，並顯示簡短原因說明（例如「客戶名單池尚未同步」），不需完整技術錯誤堆疊

### AC-8：區塊二 — 觸發權限差異化呈現（本頁僅狀態，不觸發）

- **Given** 「月名單分派就緒狀態」區塊已顯示
- **When** 使用者檢視此區塊的可操作元素
- **Then** 本頁**不提供**觸發月名單分派的按鈕（觸發動作維持在既有「觸發月名單分派」頁）
- **And** 部長 / admin 視角下，此區塊顯示「前往觸發月名單分派」導覽連結
- **And** 處長視角下，此區塊**不顯示**任何導覽至觸發頁的連結或按鈕（處長對月名單分派觸發無操作權限，比照 M07 角色矩陣），僅呈現唯讀狀態

### AC-9：區塊三 — 本月 vs 下月預計撥打總量

- **Given** 分派總覽頁已載入
- **When** 頁面呈現「預計撥打量」區塊
- **Then** 顯示本月（`current_work_ym`）與下月（`target_work_ym`）的預計總撥打量（案件數）並排比較
- **And** 若其中一個月份查無任何 active 名單或估算資料，該月份數值顯示「—」並附「本月尚無啟用名單」等說明文字，**不得**顯示 0 或任何造成誤解的數字
- **And** 此區塊之月份對比固定為「本月 / 下月」，與 AC-3 之「分派作業月份選擇器」為兩個獨立維度（選擇器影響本頁其他三個區塊看哪個月，本 AC 之本月/下月對比為固定的營運節奏參考，不受選擇器影響）

### AC-10：區塊三 — 每日撥打量圖表

- **Given** 「預計撥打量」區塊已載入
- **When** 頁面呈現每日分佈
- **Then** 以圖表呈現選定月份（AC-3 選擇器所選月份）各工作日的預估撥打量，非工作日（假日）不計入或明確標示為 0
- **And** 圖表資料點可查看當日詳細數字（如 hover 顯示件數）

### AC-11：區塊三 — 部門分佈與人均每日可行性

- **Given** 「預計撥打量」區塊已載入
- **When** 頁面呈現部門維度資料
- **Then** 顯示各部門的預估撥打量分佈（部門名稱 + 件數 / 佔比）
- **And** 顯示各部門「人均每日件數」可行性指標，超過既有負荷門檻（沿用 US-169 既有邏輯與門檻）的部門以警示樣式標示（如紅色），未設定門檻時不顯示警示（沿用 US-169 AC-4 降級顯示邏輯）
- **And** 部門在職人數為 0 導致無法計算人均值時，顯示「—」並附說明，不得顯示 0、`Infinity` 或 `NaN`（沿用 US-169 AC-2）

### AC-12：區塊三 — 處長僅見本部門撥打量數據

- **Given** 使用者為處長
- **When** 「預計撥打量」區塊呈現
- **Then** 每日圖表、部門分佈、人均可行性三者均僅呈現處長本人轄區部門的數據
- **And** 本月 / 下月總量對比（AC-9）之數字，處長視角下僅反映其轄區部門的加總，而非全公司總量；頁面需明確標示「（僅本部門）」等字樣避免與部長視角的全公司數字混淆

### AC-13：區塊四 — 最近一次月跑結果回顧

- **Given** 選定月份（AC-3 選擇器所選）存在至少一筆已完成（`completed`）的月名單分派
- **When** 頁面呈現「最近一次月跑結果」區塊
- **Then** 顯示該月最近一次完成月跑的部門「設定比例 vs 實際落差」摘要（部門名稱、設定比例、實際比例、落差），落差超出既有可接受範圍（NFR-005 既定門檻）的部門以警示樣式標示
- **And** 顯示該次月跑的 CARD_LEVEL 分布與 TIER 分布概況（各等級 / 各 TIER 的數量或佔比）
- **And** 區塊提供「查看完整結果摘要」與「查看執行歷史」連結，分別導向既有的結果摘要頁（M04）與執行歷史清單頁（M05）
- **And** 處長視角下，部門落差摘要僅顯示其轄區部門資料列（比照 AC-2 部門範圍限定規則）

### AC-14：區塊四 — 選定月份尚無已完成月跑時的空狀態

- **Given** 選定月份沒有任何 `completed` 狀態的月名單分派紀錄
- **When** 頁面呈現「最近一次月跑結果」區塊
- **Then** 顯示明確空狀態文案，例如「本月尚無已完成的月名單分派結果」，**不**自動 fallback 顯示其他月份的結果（避免使用者誤認為是選定月份的數據）
- **And** 若選定月份存在 `failed` 或 `running` 狀態的月跑（但無 `completed`），空狀態文案需反映該狀態（例如「本月月名單分派執行中，尚無可回顧結果」），而非統一顯示「尚無資料」

### AC-15：跨區塊 Loading / Empty / Error 狀態規範

- **Given** 分派總覽頁的任一區塊（名單階段待辦 / 就緒狀態 / 預計撥打量 / 最近一次月跑結果）
- **When** 該區塊對應的資料請求分別處於載入中、回傳空資料、或請求失敗（含逾時）三種情形
- **Then** 三種情形須有各自明確、可視覺區分的呈現：載入中顯示載入指示（非空白）、空資料顯示前述各 AC 定義之空狀態文案（非空白、非顯示 0 或誤導性數字）、失敗顯示明確錯誤提示（如「本區塊資料暫時無法取得，請稍後重試」）
- **And** 任一區塊發生失敗，**不得**影響其他三個區塊的正常顯示（四個區塊的資料請求彼此獨立，不互相阻擋）
- **And** 失敗提示不得以靜默空白呈現（本專案已有因逾時導致頁面靜默空白、誤導使用者的既有事故，本頁面須明確規避）

### AC-16：唯讀特性 — 頁面不執行任何寫入操作

- **Given** 使用者在分派總覽頁的任何區塊進行互動
- **When** 檢視頁面所有可操作元素
- **Then** 頁面上所有可點擊項目（KPI 卡、待辦清單項目、各類連結）行為**僅限於導覽**（跳轉至既有功能頁或聚焦既有頁面的特定區域）
- **And** 頁面本身不呼叫任何會建立、修改、刪除業務資料的 API（不觸發月名單分派、不修改名單設定、不修改比例）

### AC-17：Sidebar 導覽入口變更

- **Given** 使用者於側邊欄看到「客戶名單分派」模組群組
- **When** 展開該模組群組的頁面清單
- **Then** 「分派總覽」為該群組第 1 個項目（模組預設進入頁）
- **And** 原本位居第 1 項的「篩選欄位」（M06）調整為第 2 項，其頁面功能與路由本身不變（僅排序調整）
- **And** 使用者直接點擊「客戶名單分派」模組群組本身（若群組本身可點擊導覽）時，導向 `/assignment/overview`

## 技術備註（僅供 spec-writer / 架構師參考，非本 Story 決策範圍）

  - 區塊一（名單階段待辦）：既有名單清單 / 階段統計查詢（`GET /assignment/lists?ym=`，`stageCounts` + 各名單明細）
  - 區塊二（就緒狀態 + ETL 前置）：既有月名單分派前置條件查詢（`GET /assignment/runs/readiness?ym=`）
  - 區塊三（預計撥打量）：既有 Stage 0 部門維度每日估算（`GET /assignment/stage0/dept-estimate?ym=`，US-166/167/169 之既有邏輯與處長 scope 規則，比照 US-168）
  - 區塊四（最近一次月跑結果）：既有執行結果摘要（`GET /assignment/runs/:runId/summary`）與執行清單（`GET /assignment/runs?ym=`）
  - 本月 / 下月判斷：既有目前作業月份服務（`current_work_ym`），下月＝當月 + 1（`target_work_ym` 預設邏輯，比照 US-137/138/140）
- 是否新增一個聚合型端點（一次回傳四區塊資料）或前端分別呼叫四個既有端點，屬架構決策，由 system-architect 裁定；本 Story 僅約束「使用者感知上四區塊各自獨立載入 / 失敗」（見 AC-15），不預設後端呼叫次數
- 角色守衛：業務範圍上等同既有 `DirectorOrSectionChief` 守衛（比照 US-168 對 Stage 0 試算頁的存取調整），實際 Guard 命名與實作由 system-architect 決定
- 處長轄區判定：沿用既有 `SectionChiefScopeService.getScopeDeptCode`（見 US-168 背景說明），本 Story 不重新定義判定邏輯

## 測試案例

### TC-177-01：部長進入分派總覽頁看到全公司四區塊資料

- **Given**：部長帳號，選定月份 202608 有 10 筆 active 名單（8 ready、2 未就緒）
- **When**：部長進入 `/assignment/overview`
- **Then**：區塊一顯示五階段 KPI（含 2 筆未就緒待辦清單）；區塊二顯示「8/10 已就緒」；區塊三顯示全公司本月/下月撥打量對比與各部門分佈；區塊四顯示（若有）最近一次完成月跑摘要

### TC-177-02：處長進入分派總覽頁僅見轄區資料

- **Given**：處長帳號，轄區部門為 D003；系統另有 D001、D002 部門資料
- **When**：處長進入分派總覽頁
- **Then**：頁面顯示「轄區檢視」徽章；名單階段待辦、部門撥打量分佈、部門落差摘要僅出現 D003 資料列；不出現 D001 / D002 資料列；不顯示全公司總量／缺口類數值

### TC-177-03：user 角色整頁封鎖

- **Given**：帳號 `role = 'user'`
- **When**：導航至 `/assignment/overview`
- **Then**：主體內容不顯示，改顯示「分派總覽為部長 / 處長 / Admin 專屬功能」封鎖說明卡

### TC-177-04：切換分派作業月份重新整理四區塊

- **Given**：頁面顯示 202608 資料
- **When**：使用者於月份選擇器切換至 202607
- **Then**：四大區塊全部依 202607 重新載入；月份選擇器顯示為 202607

### TC-177-05：點擊 KPI 卡導向名單定義主頁並聚焦該階段

- **Given**：區塊一「待簽核」KPI 卡顯示 3
- **When**：使用者點擊該卡
- **Then**：導向 M01 名單定義主頁（Kanban），並聚焦 / 篩選於「待簽核」欄

### TC-177-06：點擊未完成名單待辦清單項目導向該名單詳情

- **Given**：待辦清單顯示一筆「LIST-2026080012（個別比例設定階段）」
- **When**：使用者點擊該筆
- **Then**：導向該名單之 Detail Drawer，顯示個別比例設定階段的相關資訊

### TC-177-07：ETL 來源未同步時區塊二顯示警示

- **Given**：`readiness.etlStatus` 中「客戶名單池」狀態非 completed
- **When**：頁面呈現區塊二前置檢查
- **Then**：「客戶名單池」項目以警示樣式呈現，附簡短原因說明；其餘就緒項目正常顯示

### TC-177-08：處長視角區塊二不顯示觸發連結

- **Given**：處長帳號進入分派總覽頁
- **When**：檢視區塊二
- **Then**：不出現任何「前往觸發月名單分派」的連結或按鈕；部長帳號檢視相同區塊則正常顯示該連結

### TC-177-09：下月尚無估算資料時顯示「—」而非 0

- **Given**：下月（202609）尚無任何 active 名單
- **When**：區塊三呈現本月 / 下月對比
- **Then**：下月欄位顯示「—」與「本月尚無啟用名單」說明；本月欄位正常顯示數字

### TC-177-10：部門超過人均門檻時紅色警示

- **Given**：D002 部門某工作日人均件數 20，門檻設定 15
- **When**：區塊三呈現部門可行性資料
- **Then**：D002 該日人均欄以紅色警示樣式呈現，並顯示「超過每人每日上限 15 件」提示

### TC-177-11：選定月份無已完成月跑時區塊四顯示明確空狀態

- **Given**：選定月份僅有 `failed` 狀態的月跑紀錄，無 `completed`
- **When**：頁面呈現區塊四
- **Then**：顯示反映該狀態的空狀態文案（例如提及執行失敗），而非泛用「尚無資料」；不 fallback 顯示其他月份結果

### TC-177-12：單一區塊逾時失敗不影響其他區塊

- **Given**：區塊三（預計撥打量）之資料請求逾時失敗，其餘三區塊正常回應
- **When**：頁面渲染
- **Then**：區塊三顯示明確錯誤提示（非空白）；區塊一、二、四正常顯示各自資料

### TC-177-13：頁面無任何寫入型操作入口

- **Given**：分派總覽頁完整載入
- **When**：檢視頁面所有可點擊元素
- **Then**：所有元素之行為皆為路由導覽，頁面程式碼路徑不呼叫任何建立 / 修改 / 刪除資料的 API

### TC-177-14：Sidebar 排序驗證

- **Given**：使用者展開側邊欄「客戶名單分派」模組群組
- **When**：檢視項目順序
- **Then**：「分派總覽」為第 1 項；「篩選欄位」為第 2 項；其餘既有項目相對順序不受影響

## 開放問題

- [ ] **OQ-177-01**：區塊四「最近一次月跑結果」若選定月份完全無任何月跑紀錄（連 failed/running 都沒有）與「有 failed/running 但無 completed」是否需要視覺區分兩種不同空狀態文案，或統一為一種？本 Story AC-14 已要求兩者文案有所區分，但具體措辭由 spec-writer 確認。
- [ ] **OQ-177-02**：「未完成名單待辦清單」（AC-5）若單月未就緒名單數量很多（例如 50+ 筆），是否需要分頁、捲動高度限制、或僅顯示前 N 筆＋「查看全部」連結？本 Story 未規定顯示上限，由 spec-writer / ui-ux-designer 裁定。
- [ ] **OQ-177-03**：本頁是否需要提供「重新整理全部區塊」的單一按鈕，或僅依賴各區塊獨立的重試機制（AC-15 錯誤狀態）？本 Story 未強制要求全域重新整理按鈕，若業務需要建議另行確認。
