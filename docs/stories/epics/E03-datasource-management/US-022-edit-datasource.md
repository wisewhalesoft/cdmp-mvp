# US-022：編輯資料來源

> **Story ID**：US-022
> **Epic**：[E03 — 資料來源管理](epic-brief.md)
> **優先級**：Must Have
> **階段**：Phase 1（MVP）
> **預估點數**：3

---

## User Story

**As a** Admin（管理者）
**I want** 編輯現有資料來源的設定
**So that** 當資料庫設定變更時，我可以更新連線詳細資訊

---

## 驗收標準

### AC-1：成功編輯
- **Given** Admin 正在查看某資料來源的詳細資料
- **When** Admin 修改連線欄位（名稱、主機位址、連接埠、資料庫名稱、帳號或密碼）並點擊「儲存」
- **Then** 系統更新設定，加密任何新輸入的憑證，顯示成功訊息，並將連線狀態重設為「未知」

### AC-2：密碼欄位行為
- **Given** Admin 開啟某資料來源的編輯表單
- **When** 表單載入完成
- **Then** 密碼欄位顯示提示文字（例如「留空以保留現有密碼」），且不顯示實際密碼內容

### AC-3：名稱唯一性驗證（編輯時）
- **Given** 系統中已存在另一個名稱為「Production DB」且資料庫名稱為「prod_db」的資料來源
- **When** Admin 將當前資料來源的名稱改為「Production DB」且資料庫名稱改為「prod_db」
- **Then** 系統顯示「相同資料庫下已存在此名稱的資料來源」，且不儲存變更

### AC-3b：不同資料庫允許相同名稱（編輯時）
- **Given** 系統中已存在另一個名稱為「Production DB」且資料庫名稱為「prod_db」的資料來源
- **When** Admin 將當前資料來源的名稱改為「Production DB」但資料庫名稱設為「staging_db」
- **Then** 系統成功儲存變更，不顯示重複錯誤

---

## Technical Notes

- 端點：`PUT /api/datasources/:id`
- 若 Request 中密碼欄位為空或 null，保留現有密碼
- 若 Request 中密碼欄位有值，加密後更新
- 編輯後將狀態重設為「unknown」，觸發重新驗證
- 稽核記錄：記錄變更的欄位（但不記錄憑證值）

---

## 測試案例

| # | 測試案例 | 預期結果 |
|---|---------|---------|
| 1 | 編輯主機位址與連接埠 | 更新成功 |
| 2 | 以新密碼編輯 | 密碼重新加密 |
| 3 | 不變更密碼進行編輯 | 現有密碼保留 |
| 4 | 將名稱＋資料庫名稱改為與其他記錄相同 | 顯示重複錯誤訊息 |
| 4b | 名稱相同但資料庫名稱不同 | 儲存成功 |
| 5 | 編輯後的連線狀態 | 重設為「未知」 |
| 6 | 非 Admin 嘗試編輯 | 回傳 403 Forbidden |
