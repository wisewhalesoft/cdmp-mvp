# US-023：刪除資料來源

> **Story ID**：US-023
> **Epic**：[E03 — 資料來源管理](epic-brief.md)
> **優先級**：Should Have
> **階段**：Phase 1（MVP）
> **預估點數**：2

---

## User Story

**As a** Admin（管理者）
**I want** 刪除一個資料來源設定
**So that** 我可以移除不再需要的資料庫連線

---

## 驗收標準

### AC-1：確認後刪除
- **Given** Admin 正在查看某資料來源
- **When** Admin 點擊「刪除」，並在確認對話框中確認操作
- **Then** 系統移除該資料來源，顯示成功訊息，且該筆記錄從清單中消失

### AC-2：取消刪除
- **Given** Admin 已點擊「刪除」且確認對話框已出現
- **When** Admin 點擊「取消」
- **Then** 資料來源未被刪除，對話框關閉

### AC-3：確認對話框內容
- **Given** Admin 點擊某資料來源的「刪除」按鈕
- **When** 確認對話框出現
- **Then** 對話框顯示資料來源名稱，以及警示訊息：「您確定要刪除 [名稱] 嗎？刪除後將不再顯示於清單中。」

### AC-4：軟刪除資料保留
- **Given** Admin 已確認刪除某資料來源
- **When** 系統執行刪除操作
- **Then** 系統設定 `deleted_at` 時間戳記（軟刪除），該筆記錄保留於資料庫中但不再出現於任何清單或儀表板查詢結果

---

## Technical Notes

- 端點：`DELETE /api/datasources/:id`
- 採用軟刪除：設定 `deleted_at` 時間戳記，資料保留於資料庫中
- 所有清單、儀表板、健康檢查查詢需過濾 `deleted_at IS NULL`
- 軟刪除的資料可由 DBA 透過資料庫層級復原（將 `deleted_at` 設為 NULL）
- 確認對話框必須要求使用者明確執行操作

---

## 測試案例

| # | 測試案例 | 預期結果 |
|---|---------|---------|
| 1 | 確認後刪除 | 資料來源已移除 |
| 2 | 取消刪除 | 資料來源保留，對話框關閉 |
| 3 | 刪除不存在的資料來源 | 回傳 404 Not Found |
| 4 | 確認已從清單中移除 | 刪除後不再出現於清單 |
| 5 | 非 Admin 嘗試刪除 | 回傳 403 Forbidden |
| 6 | 確認資料庫中仍有紀錄 | `deleted_at` 欄位已設定，資料保留 |
| 7 | 已刪除的資料來源不出現在儀表板 | 健康檢查與儀表板排除軟刪除項目 |
