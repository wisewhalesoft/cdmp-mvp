# US-024：測試資料來源連線

> **Story ID**：US-024
> **Epic**：[E03 — 資料來源管理](epic-brief.md)
> **優先級**：Must Have
> **階段**：Phase 1（MVP）
> **預估點數**：3

---

## User Story

**As a** Admin（管理者）
**I want** 測試已設定資料來源的連線狀態
**So that** 我可以在依賴該資料來源之前，確認資料庫可連線且憑證正確

---

## 驗收標準

### AC-1：連線測試成功
- **Given** 資料來源以有效的連線參數設定完成
- **When** Admin 點擊「測試連線」
- **Then** 系統嘗試連線，顯示含回應時間的成功訊息（例如：「連線成功，回應時間 120ms」），並將狀態更新為「已連線」

### AC-2：連線測試失敗
- **Given** 資料來源以不正確的參數設定（錯誤的主機位址、連接埠或憑證）
- **When** Admin 點擊「測試連線」
- **Then** 系統顯示具描述性的錯誤訊息（例如：「連線被拒：無法連至主機」或「驗證失敗：憑證不正確」），並將狀態更新為「已中斷」

### AC-3：連線逾時
- **Given** 資料來源目標無法連線（網路問題）
- **When** Admin 點擊「測試連線」
- **Then** 系統在 10 秒後逾時，顯示「連線逾時（10 秒）」，並將狀態設為「已中斷」

---

## Technical Notes

- 端點：`POST /api/datasources/:id/test`
- Response：`{ success: boolean, message: string, responseTime?: number }`
- 逾時：10 秒（依 NFR-002 規範）
- 連線測試流程：開啟連線 -> 執行簡易查詢（例如 `SELECT 1`）-> 關閉連線
- 更新資料來源的 `status` 與 `lastTestedAt` 欄位
- 測試執行期間顯示載入中動態效果（Loading Spinner）
- 憑證僅在伺服器端解密用於測試，絕不傳送至用戶端

---

## 測試案例

| # | 測試案例 | 預期結果 |
|---|---------|---------|
| 1 | 測試有效的 MySQL 連線 | 成功，含回應時間 |
| 2 | 測試有效的 PostgreSQL 連線 | 成功，含回應時間 |
| 3 | 測試有效的 SQL Server 連線 | 成功，含回應時間 |
| 4 | 使用錯誤密碼測試 | 顯示驗證失敗訊息 |
| 5 | 測試無法連線的主機 | 10 秒後逾時 |
| 6 | 使用錯誤連接埠測試 | 顯示連線被拒訊息 |
| 7 | 測試後狀態更新 | 狀態反映測試結果 |
| 8 | 測試期間的載入狀態 | 顯示 Spinner 動態效果 |
| 9 | 非 Admin 嘗試測試 | 回傳 403 Forbidden |

- [ ] 測試執行期間的載入動態效果
- [ ] 成功時顯示含回應時間的成功訊息
- [ ] 失敗時顯示具描述性的錯誤訊息
- [ ] 10 秒逾時機制實作完成
- [ ] 資料庫中的 `status` 與 `lastTestedAt` 欄位已更新
- [ ] 測試後連線已正確關閉
- [ ] 所有驗收標準的單元測試通過
