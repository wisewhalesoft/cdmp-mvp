# NFR-001：安全性需求

> **NFR ID**：NFR-001
> **類別**：Security（安全性）
> **優先級**：P0（Critical）
> **階段**：Phase 1（MVP）
> **最後更新**：2026-03-06

## 需求陳述

### NFR-001.1：驗證安全性
所有使用者 Session 必須透過安全的 Token 機制（如 JWT）進行驗證。Token 在閒置超過 8 小時後必須自動失效。

### NFR-001.2：授權強制執行
每個 API 端點必須強制執行基於角色的存取控制（RBAC）。未授權的存取嘗試必須回傳 HTTP 403 並留下日誌記錄。

### NFR-001.3：密碼安全性
密碼必須使用 bcrypt（或同等演算法）進行雜湊處理，最低成本因子（cost factor）為 10。明文密碼絕不能被儲存或出現在任何日誌中。

### NFR-001.4：資料來源憑證保護
資料庫連線憑證（密碼、連線字串）必須使用 AES-256 或同等強度演算法在靜態時加密。憑證絕不能出現在 API 回應或應用程式日誌中。

### NFR-001.5：傳輸安全性
用戶端與伺服器之間的所有通訊必須使用 HTTPS（TLS 1.2 以上）。內部服務間通訊也必須加密。

## 驗收標準

### AC-1：Token 過期驗證
- **Given** 使用者目前有一個有效的 Session
- **When** Session 閒置時間超過 8 小時
- **Then** Token 失效，使用者必須重新進行驗證

### AC-2：未授權存取防護
- **Given** User 角色帳號嘗試存取 Admin 專屬端點
- **When** 請求被系統處理
- **Then** 系統回傳 HTTP 403 Forbidden，並記錄該次嘗試至日誌

### AC-3：密碼儲存驗證
- **Given** 一個新帳號以密碼建立
- **When** 密碼被儲存至資料庫
- **Then** 密碼以 bcrypt 雜湊形式儲存（非明文），成本因子 >= 10

### AC-4：憑證遮罩驗證
- **Given** 一筆資料來源記錄包含資料庫連線憑證
- **When** 透過 API 取得該記錄
- **Then** 密碼欄位以遮罩方式呈現（例如「****」），且絕不以明文回傳

## 受影響的 Stories

| Story ID | 影響說明 |
|----------|---------|
| US-001 | Admin 登入必須使用安全 Token 驗證 |
| US-002 | User 登入必須使用安全 Token 驗證 |
| US-003 | 登出必須在伺服器端使 Token 失效 |
| US-010 | 建立帳號時必須雜湊密碼 |
| US-020 | 資料來源憑證必須加密後儲存 |
| US-022 | 編輯憑證時必須維持加密保護 |
| US-024 | 測試連線必須安全使用憑證，不得在日誌中記錄 |

## 驗證方式

- 對所有 API 端點執行自動化安全掃描（OWASP ZAP 或同等工具）
- 密碼雜湊與憑證加密的程式碼審查清單
- RBAC 繞過嘗試的滲透測試
- 日誌稽核，確認任何日誌輸出中不包含明文憑證
