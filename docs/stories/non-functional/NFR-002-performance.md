# NFR-002：效能需求

> **NFR ID**：NFR-002
> **類別**：Performance（效能）
> **優先級**：P0（Critical）
> **階段**：Phase 1（MVP）
> **最後更新**：2026-03-06

## 需求陳述

### NFR-002.1：API 回應時間
在正常負載下，標準 CRUD 操作的 API 回應時間第 95 百分位數必須低於 500ms。

### NFR-002.2：並發使用者數
系統必須支援至少 100 位並發已驗證使用者，且不得使回應時間超出可接受閾值。

### NFR-002.3：資料來源連線測試時間
資料來源連線測試操作必須在 10 秒內回傳結果（成功或失敗）。系統必須具備逾時機制以終止長時間未回應的連線嘗試。

### NFR-002.4：儀表板載入時間
資料來源狀態監控儀表板必須在 2 秒內完成初始內容渲染，包含最多 50 個資料來源的彙整狀態資料。

### NFR-002.5：清單／搜尋效能
帳號清單與資料來源清單端點在資料量不超過 1,000 筆時，必須在 500ms 內回傳分頁結果。

## 驗收標準

### AC-1：CRUD 回應時間
- **Given** 系統處於正常負載（最多 50 位並發使用者）
- **When** 發出一筆 CRUD API 請求
- **Then** 第 95 百分位數回應時間低於 500ms

### AC-2：並發使用者支援
- **Given** 100 位使用者同時完成驗證並進行操作
- **When** 他們執行標準操作（清單瀏覽、查看、編輯）
- **Then** 系統回應時間維持在單一使用者基準值的 2 倍以內

### AC-3：連線測試逾時
- **Given** Admin 對某資料來源發起連線測試
- **When** 目標資料庫無回應
- **Then** 測試在 10 秒內逾時，並回傳失敗結果

### AC-4：儀表板效能
- **Given** 系統中設定了 50 個資料來源
- **When** Admin 開啟狀態監控儀表板
- **Then** 儀表板含狀態資料在 2 秒內完成渲染

## 受影響的 Stories

| Story ID | 影響說明 |
|----------|---------|
| US-011 | 帳號清單必須在 500ms 內回傳分頁結果 |
| US-021 | 資料來源清單必須在 500ms 內回傳分頁結果 |
| US-024 | 連線測試必須強制 10 秒逾時機制 |
| US-025 | 儀表板必須在 50 個資料來源時 2 秒內載入完成 |

## 驗證方式

- 使用 k6 或 JMeter 模擬 100 位並發使用者進行負載測試
- 含百分位數追蹤的 API 回應時間監控
- 以無法連線的資料庫目標驗證連線測試逾時機制
- 在不同資料來源數量下進行儀表板渲染效能基準測試
