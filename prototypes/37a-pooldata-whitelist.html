F075 — 篩選欄位管理（M06 代碼維護擴充）

管理可作為名單條件的 OBPOOLDATA 欄位；每欄位標記 field_type（numeric / categorical / date），驅動 US-106 新名單定義表單的條件元件型態。 停用為軟刪除（is_active = false），不回溯既有名單條件（BR-3）。 資料表 pooldata_field_whitelist · 初始 Seed 8 筆（來源 SP_INFOT_ASSIGNEXPORTNAMELIST_st1_list.sql）。

權限：部長 + Admin 可新增 / 編輯 / 停用；處長 + 業務僅可查看（不渲染寫入按鈕；後端寫入端點亦回 403 E07_FORBIDDEN_DIRECTOR_ONLY）。請使用上方角色切換器測試。

F075 商業規則摘要

  • BR-1：column_name 為唯一鍵，新增時不分啟用 / 停用一律檢查重複（違反回 409 POOLDATA_FIELD_DUPLICATE）。
  • BR-3：停用「不回溯」既有名單條件，月跑 Stage 1 直接讀 ob_list_definition JSONB，不 join pooldata_field_whitelist 驗證。
  • BR-4：field_type 由 categorical 改為其他類別時，不自動刪除 F076 既有可選值（軟停用，deactivation_reason = 'field_type_changed'，PO 決議 F076-C）。
  • BR-7：舊名單（F050/F051）沿用固定欄位邏輯，本篩選欄位管理僅影響 US-106 後續新名單定義。

    新增 / 修改寫入 assignment_audit_log（entity_type = pooldata_field_whitelist、entity_id = column_name）。違反唯一性 → 409 POOLDATA_FIELD_DUPLICATE。

    變更欄位類別

    欄位 PROD_KIND 從
    categorical → numeric

    此操作將自動停用 3 個可選值（BR-4 / F076-C）

    • F076 既有可選值將 SET is_active = false，deactivation_reason = 'field_type_changed'
    • 不執行 hard delete，可於 F076 列表 ?includeInactive=true 查詢歷史
    • 既有名單條件不受影響（BR-3 不回溯）
    • 寫入 assignment_audit_log（action=UPDATE + 批次 DISABLE）

    停用篩選欄位

    確定停用 SETTLE_SRC「他行代償」？

    軟刪除（is_active = false）

    • 新名單定義（US-106）將不再顯示此欄位選項
    • 既有名單條件不被回溯修改（BR-3）
    • 寫入 assignment_audit_log（action=DISABLE）
